# T2 单动作输入仪器说明

更新：2026-09-23  
仪器：`scripts/t2_input_probe.py`

## 1. 仪器行为

该脚本用于记录 Windows `SendInput` 的单个 key-down/key-up 发送结果和人工效果标签。

- 默认模式是 dry-run，不发送输入。
- live 模式要求输入精确短语 `SEND ONE KEY`。
- 每次发送前要求人工确认，并在倒计时后重新核对前台窗口标题。
- 标题不匹配时不发送。
- 每次发送后由操作者记录 `ok`、`no_effect`、`wrong_effect`、`unknown`、`blocked` 或 `forbidden`。
- 结果不保存实际窗口标题。
- 当前脚本要求 `--trials` 为正整数；该值是操作者选择的运行参数，不是可靠性标准。

## 2. 已完成检查

执行过的 dry-run：

```powershell
python scripts/t2_input_probe.py --key 1 --trials 3 --output results/t2_input_probe_dry_run.json
```

实际结果：

- `mode` 为 `dry-run`；
- 3 条记录均为 `not_sent`；
- `sent` 为 `0`；
- 结果不含识别性窗口、账号或设备信息。

未解锁 live 调用也已检查：退出码为 `2`，输出 `Not armed; no input sent.`，未生成结果文件。

Windows 64 位 ABI 检查中，完整 `INPUT` union 的 `ctypes.sizeof(INPUT)` 为 40 bytes。早期仅包含 keyboard 成员的定义为 32 bytes，已修正。

## 3. 尚未发生

- 没有对文本编辑器发送真实输入。
- 没有对 WoW 或任何其他游戏窗口发送真实输入。
- 没有游戏内效果记录。
- 没有 Blocked/Forbidden 的运行时观察。
- 没有支持 `30/30`、单次预检或最多一次重测作为项目门槛的数据基线。

## 4. 结果含义

`SendInput` 返回成功只表示 Windows 接受了两个 `INPUT` 结构，不证明目标应用产生了预期动作。人工 `effect` 字段用于记录可见效果；动作效果、限制事件和授权是不同问题。

前台检查、逐次确认、key-up 配对和手动中止能力是该仪器的防误输入属性，不是对自动化技术路线的结论。
