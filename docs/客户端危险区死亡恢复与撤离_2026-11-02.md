## 一、为什么客户端路线用不了 Detour

AGENTS.md 写的是"幽灵时预先规划沿 Detour 可达路径"。Detour 导航在纯网络路线里是本机编译的
`agent_wow_nav.exe`，它吃**世界坐标**（`nav <mmaps目录> <地图id> <x y z> <x y z>`）。

客户端路线拿不到世界坐标：**3.3.5a 没有 `GetUnitPosition`**（探针实测 `err=no api`），
`GetPlayerMapPosition` 给的是**区域内归一化坐标**，与服务端 navmesh 之间没有可用换算；
本机也没有 `MapAreaInfo.dbc`。

因此本路线改用**路径记忆**：

- 幽灵走的每一步都是服务端认可的移动，**走过的路径就是可行路径**；
- `scripts/client_path_memory.py` 记录路径，`route_back()` 把它倒过来，
  撤离就沿着这条走过的路回墓地，**不是直线的弦**；
- 路径长度就是**可行路径距离**，两次死亡可以直接比较。

这是与 AGENTS.md 的一处**有理由的偏离**，原因如上，已在此记录。

## 二、本轮定位的一个总根因

2026-11-02 之前的一批怪现象（面板数据陈旧、AddOns 报错弹窗、UI 里有目标而探针看不到、
TAB 选目标选不中、读数解码失败）**都是同一个 bug**：

```lua
-- 错：3.3.5a 的 UnitClassification 返回的是单词，不是数字
classification = UnitClassification("target")   -- "normal"
number(classification, 1)                        -- math.floor("normal") -> 抛错
```

Lua 错误：

```
WowProbeLive.lua:178: bad argument #1 to 'floor' (number expected, got string)
```

**只要选中目标，探针的 `update()` 每次都抛错**，于是：

- 面板停在最后一次成功写入的那一帧 → 读数是几百秒前的旧值；
- 像素条被冻结在半写状态 → 校验和不过 → "telemetry absent or invalid"；
- 错误累积 → 客户端弹出 "Your AddOns are experiencing a large number of errors"（模态）。

修法：把单词映射成数字（normal=1 / elite=2 / rareelite=3 / worldboss=4 / rare=5 /
trivial=6 / quest=7），并把 `number()` 改成 `tonumber(value) or 0`，任何非数字都不会再弄坏整块面板。

**教训**：探针里凡是"看起来像数字"的外来值都要 `tonumber` 兜底；
判定"数据对不上"之前，先把客户端的 Lua 错误打开看
（`/console scriptErrors 1`，错误会出现在聊天框里）。

## 三、满屏改造与满屏特有的四个坑

按用户建议，客户端改成**满屏 1920×1080**：改 `WTF/Config.wtf` 的 `SET gxWindow "0"`
（先停客户端，否则退出时会被覆盖；原文件备份为 `Config.wtf.bak-20261102`）。

满屏之后游戏图与屏幕一一对应，点击坐标不用再换算，但带来四个新问题：

| 问题 | 原因 | 修法 |
| --- | --- | --- |
| `post_key` 的按键全部无效 | 满屏时 `GxWindowClassD3d` 是**离屏 160×28 的占位窗**，PostMessage 到它进不了游戏 | `lab_driver5.post_key` 改用 `SendInput` |
| 窗口句柄失效（error 1400） | 切场景时客户端会重建窗口 | 新增 `lab_driver5.game_window()`，每次交互前重新取句柄 |
| 几何换算全错 | 占位窗的客户区是 160×28 | `client_geometry.is_fullscreen()` 特判：满屏时恒等映射 |
| 遥测突然全部解码失败 | **模态窗口**（死亡对话框、游戏菜单）把探针冻结在半写状态，校验和不过 | `client_read_fresh.read_or_dismiss()`：先关掉模态再读 |

补充：`chat_open` 的旧判据（`ChatFrame1InputFrame:IsShown()`）在 3.3.5a 是**假阳性**
（聊天框关了它仍然报 true），会让驱动误以为聊天还开着而反复按 ESC，
反而把游戏菜单按出来。改成只看 `ChatEdit_GetActiveWindow()`。

## 四、任务流程

| 阶段 | 判据 | 动作 |
| --- | --- | --- |
| `RELEASE` | 角色死了但客户端还不知道尸体在哪 | 点死亡对话框的 "Release Spirit"，角色变成墓地里的幽灵 |
| `GHOST` | `corpse_exists=1` | 转向尸体并前走；走不通就沿反方向绕行 |
| `REVIVE` | 距离尸体 ≤ 0.004 | 点 "Resurrect now?" 的 Accept 按钮 |
| `ESCAPE` | 复活确认 | **立即**沿记录的路径跑回墓地，不插入任何无关查询 |
| `SAFE` | 到达墓地、存活、脱战 | 结束 |

朝向与地图的约定是实机标定出来的（`lab_client_heading_calib.py` /
`lab_client_walk_calib.py`），不能改：

| 项目 | 值 |
| --- | --- |
| 地图 x / y | 向东为正 / 向南为正 |
| 朝向 θ | 自北**逆时针**为正 |
| 行走位移 | `u(θ) = (-sin θ, -cos θ)` |
| LEFT / RIGHT | θ 增大 / θ 减小 |
| 转向速率 | π rad/s |

朝向尸体的目标角：`atan2(pos_x - corpse_x, pos_y - corpse_y)`。

## 五、再死一次的处理

`client_danger_recovery.DangerRecovery` 在第二次死亡时会：

1. 把新尸体记进 `corpses` 列表；
2. 以**新尸体的可行路径长度**（走过的路径长度）与上一次比较，
   判断是否更接近墓地；
3. 从新尸体重新规划，回到墓地。

本轮实机只跑通了第一次死亡（狼在标准位置，尸体离墓地 0.0146）；
第二次死亡需要在一个更危险的怪（6 级精英森林蜘蛛）旁边再制造一次，
本轮没有做，**这是已知缺口**。

## 七、怎么再跑一次

```
scripts/lab_client_danger_setup.py        # 挨打到死
scripts/lab_client_danger_recovery.py     # 回来、复活、撤离
scripts/lab_client_relogin_verify.py      # 重登复核
```

驱动任务运行期间**不要并发跑其它客户端脚本**（隐藏窗口会抢前台焦点）。
