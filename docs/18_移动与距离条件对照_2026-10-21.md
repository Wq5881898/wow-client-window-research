# 移动与距离条件对照（2026-10-21）

## 已验证

本地 3.3.5a / AzerothCore，角色 Syra，GM 模式开启。
同一目标 Lothos Riftwaker（GUID `0xF1300038330202BB`）的 `CheckInteractDistance("target",4)` 在位移前后及恢复后呈现 `1 → nil → 1`。

| 场景 | 目标有效 | 距离条件返回 | 玩家生命 |
|---|---|---|---|
| distance_near | 是 | 1 | 142 |
| distance_far | 是 | 1 | 142 |
| distance_farther_4s | 是 | nil | 142 |
| distance_recovered | 是 | 1 | 142 |

短段后退截图显示角色从台阶附近移动到下方平台，证明 SendInput 持续按键可以产生实际移动。再后退 4 秒后落入熔岩，截图显示角色已在熔岩中，距离条件变为 nil。该样本包含下落及高度变化，不能解释为精确水平距离或阈值测量。

最终通过 GM 命令 `.go creature id 14387` 回到 Lothos 附近，截图与目标名均确认恢复，生命 142，非战斗；目标继续选中，距离条件恢复为 1。没有获得精确原坐标复位。

## 排错与无效样本

- 初次聊天框状态未同步，出现普通聊天文本 `s/wp once ...`；这些尝试不是有效命令执行证据。
- 对聊天前无条件发送 Escape 会在聊天未打开时清除目标，因此 `distance_back_2s` 虽然采集成功，但目标为 nil，其距离 nil 不得用作超距证据。
- 最终命令配方使用 PostMessage Enter 打开、WM_CHAR 输入、PostMessage Enter 提交；不再每条命令前按 Escape。
- 首次恢复错误地把客户端 GUID 的低位数字当作数据库 spawn ID，`.go creature 131771` 将角色传到 Wintergrasp 的其他 NPC。随后改用明确的模板 ID 14387 成功回到 Lothos。客户端 GUID 不应直接推断为数据库 spawn ID。
- 摘要按场景保留最后一次记录；早期同名失败样本仍在原始 SavedVariables 中。

## 证据与复现入口

- `scripts/lab_distance_scenarios.py`：交互会话任务入口，持续按键限制为 4 秒以内，并在 finally 中释放按键。
- `scripts/summarize_distance_scenarios.py`：提取标量结果，校验同一 GUID 与 `1/1/nil/1` 返回序列。
- `results/distance_scenarios_2026-10-21.json`：源文件 SHA-256、结果与排除原因。
- `.cache/desktop-check/distance_near.png`、`distance_far.png`、`distance_farther_4s.png`、`distance_recovered.png`：画面证据。
- 原始数据：角色 Syra 的 SavedVariables / WowProbeWotLK.lua，所有有效场景已 `/reload` 落盘。

## 能力边界与下一步

目前证明外部持续键盘输入可改变角色位置，且只读插件可以观察同一目标距离条件的变化。没有证明自动路径规划、精确距离、无 GM 模式存活或战斗能力。

后续距离阈值实验应移至平坦区域，采用更短分段并先获取可靠位置观测；战斗实验需独立控制 GM 模式、目标等级与清理流程。
