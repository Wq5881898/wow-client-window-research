## 1. 技术方向（可定死）

个人账号、Forever、普通开放世界中的自动化技术是否成立。当前讨论的最小落地场景是：固定区域、固定目标、全程旁观。这是技术收窄，不是产品范围声明。

方向不包括：需求发现、定价、访谈、发布和商业化。那些不是本预研要定的东西。

## 2. 技术路径（路径可定死，节点未证实）

落地拆成四段。顺序是结构，不是关卡。任一段失败只否定该段，不自动改方向。

```text
观察 → 出口 → 决策 → 执行
```

| 段 | 选定路径 | 现有依据 | 落地缺口 |
|---|---|---|---|
| 观察 | 第三方 addon 读文档化 API：build/限制、玩家位置、已选目标后的 Unit、Assisted Combat | 归档 dump + `api_lint.py` 名称匹配；Secret Values 分档已做 | 目标客户端未装；无调用、无可读性、无场景样本 |
| 出口 | 优先 SavedVariables；聊天和屏显作并列候选，不混成一条 | 机制资料已归档；无到达率 | 无 reload/logout 后的文件样本，无像素样本 |
| 决策 | 本地规则/状态机。在线模型不进热循环 | `bot_contract.py`/`bot_sim.py` 是合成校验；`lat*` 样本为秒到数十秒 | 合成字段 ≠ Forever 字段 |
| 执行 | Windows 标准输入（单键仪器已存在） | `t2_input_probe.py` dry-run 与 64-bit `INPUT` 40 bytes | 未向任何窗口发送；无游戏效果 |

不选入当前主路径、仅作对照的技术：

- 纯视觉观察：API 被 secret/NIL 挡住时才成为替代观察，不是现在要先做的主路径。
- 进程内存、注入、驱动、封包：高风险，只允许非操作性对照，不在当前落地路径里实现。
- 云端热决策：已被已有延迟样本削弱，不作为控制环方案。

最小场景对路径的含义：固定目标减少“敌人集合感知”，不减少位置、目标失效、出口和执行这四段。采集不是最小场景必经节点；G6 旧枚举方案已静态失败。

## 3. 可行性（分层定，不能整句定死）

| 层 | 状态 | 含义 |
|---|---|---|
| 方向可行性 | 成立 | 问题清楚，值得做技术落地 |
| 路径可行性 | 纸面自洽，待证伪 | 四段都有静态或仪器依据，没有任何一段已在 Forever 真机闭合 |
| 观察可行性 | 未知 | dump 里有候选；Secret Values 可能切掉关键字段 |
| 出口可行性 | 未知 | 机制存在；到达、延迟、乱序未测 |
| 决策可行性 | 仅合成 | 能在假世界里跑；不能外推击杀/死亡/卡住 |
| 执行可行性 | 未知 | 操作系统层仪器在，游戏层效果无 |
| 闭环可行性 | 未知 | 四段都通才谈闭环 |
| 合同/检测可行性 | 未授权 | EULA 有未授权自动控制文字；用户自行承担个人账号风险。这不是技术可行证明 |

当前不能写“可行”或“不可行”。能写的是：主路径已选定，证伪点已明确，缺 Forever 客户端上的观察与执行记录。

本机 Python 已经做过的，算仪器可行性，不算游戏可行性：静态 lint、合成仿真、端点延迟、输入 dry-run。这些应继续当落地脚手架，而不是再开文档层。

## 4. 同类产品（按技术路径归类，不是市场分析）

仓库原有材料几乎只留下 Zygor（公开辅助）和 Glider（MDY 历史案件）。下面按与本路径的关系归类。条目是公开产品类别与已知形态，不是推荐使用，也不证明 Forever 上可复制。

| 类别 | 例子 | 观察 | 出口 | 决策 | 执行 | 与本项目关系 |
|---|---|---|---|---|---|---|
| 官方/准官方循环提示 | Assisted Combat | 游戏内 | 不需要外挂出口 | 暴雪侧 | 玩家按键 | 本路径观察段的候选，不是成品 bot |
| 合法插件辅助 | WeakAuras、Hekili、GSE | addon API | 游戏内 UI | 显示/宏序列 | 玩家按键 | 观察+决策的开源参照；通常不自动执行 |
| 路线/任务辅助 | Zygor 等 | addon + 内容包 | 游戏内箭头/窗 | 内容更新 | 玩家操作 | 证明“插件观察+提示”产品形态存在；不是全自动 |
| 像素/图像 bot | 各类画面点击器 | 截图/找色 | 进程外 | 本地规则 | 键鼠 | 观察走视觉、执行走输入；本路径的备援形态 |
| 完整战斗/采集 bot | 历史上 Glider、HonorBuddy 及私服/地下城同类 | 常含内存/注入或私有 API | 进程内 | 完整状态机 | 自动 | 证明全自动技术曾经落地；实现手段与风险超出当前主路径 |
| 驱动/内核级 | 各类付费加速器传闻与地下城方案 | 不定 | 不定 | 不定 | 驱动输入 | 明确不纳入当前落地路径 |

对落地有用的结论只有三条：

1. “观察用 addon、执行靠玩家”是公开、可参照的成熟层。
2. “观察用 API 或画面、执行用外部键鼠”是全自动常见层，也是本路径要证伪的层。
3. “读内存/注入”是历史全自动常用层，本项目当前不走。

需求侧结论不需要从这些产品反推。它们只用来对照技术分层。

## 5. 开源与可引用代码（当前仓库几乎空白）

已进本仓库、可直接用的开源/镜像：

- `Ketho/wow-ui-source-forever` 的生成 API 文档（`sources/forever_dumps/`）。这是观察段的静态语料，不是 bot。
- 本仓库自己的仪器：`scripts/api_lint.py`、`bot_contract.py`、`bot_sim.py`、`t2_input_probe.py`。

尚未进仓库、但对齐本路径、属于公开插件/工具源码的参照类：

- WeakAuras、Hekili、GSE：如何读 Unit/法术/循环并在约束下更新 UI。
- Blizzard/Gethe 的 UI source 与 Ketho 各分支：核对 Forever 与正式服 API 差。

尚未作为源码对照归档、且不应在当前主路径里复制实现的：

- 各类完整 bot、内存库、注入器、驱动键鼠。它们证明“有人做过闭环”，不构成本项目的实现说明书。

开源缺口是预研里最大的材料洞：同类自动执行的公开源码没有按观察/出口/决策/执行拆过，也没有和 Forever dump 对过。下一步技术工作应补这份对照，而不是再写计划。对照方式是架构拆解和接口清单，不是把 bot 源码搬进本仓库当可运行产品。

## 6. 技术落地现在缺什么

按优先级，都是技术物件，不是文档计划：

1. **Forever 客户端** — 没有它，观察/出口/执行三段都不能闭合。这是落地硬条件。
2. **只读探针 addon 源码** — 把 dump 里的候选变成可加载记录器；本机无 WoW 也可以先写，不能冒充已跑。
3. **竞品/开源的路径拆解表** — 每个参照物填观察/出口/决策/执行，并标注是否触及 Secret Values、SavedVariables、外部输入。
4. **dump 钉死** — 文件哈希，避免静态语料被重下覆盖。
5. **真机后的第一批证伪** — build 对照、位置、已选目标 Unit、Assisted Combat；执行段仍单独做。

不缺：需求论证、访谈、商业模式、阶段计划和阈值。那些从主线拿掉。
