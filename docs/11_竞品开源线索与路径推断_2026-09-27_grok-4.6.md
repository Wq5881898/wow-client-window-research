## 1. 从公开代码能定死的一层

公开、仍在维护或刚停更的插件，技术形态高度一致：

```text
addon 观察 API → 本地算出/显示下一步 → 玩家提供硬件事件
```

| 参照 | 观察 | 决策 | 执行 |
|---|---|---|---|
| Hekili | Unit/光环/冷却/nameplate | 本地 APL，向前模拟 | 玩家按推荐键 |
| GSE | 宏栈，几乎不感知战斗 | 预写序列 | **每次点击**送一块命令；自述不能破规则，一击一个 GCD |
| WeakAuras | 触发器读状态 | 显示/音效 | 玩家看屏 |
| Questie / Zygor | 任务与路线数据 | 箭头/窗 | 玩家走和点 |
| SimulationCraft | 不进游戏 | 离线 APL | 无 |
| 官方 Assisted Combat | 游戏内状态 | 暴雪侧下一技能 | 玩家按 |

GSE 是最接近“自动循环”的开源物，仍然卡在保护函数上：没有硬件事件就不能施法。SecureActionButtonTemplate 的公开机制也是把保护动作绑到按钮，而不是给任意 Lua 定时器。

**推断 F1（执行段）：** 无人值守闭环不能做在 addon 里。CastSpellByName、UseAction、MoveForwardStart、JumpOrAscendStart、InteractUnit 在 wiki 上均标 restricted，且带 forever + 1.60.1。Forever dump 另有 `ADDON_ACTION_BLOCKED` / `FORBIDDEN`。当前主路径的执行段只能在进程外标准输入；这不是风格选择，是公开约束。

## 2. Forever 特有的观察风险

Hekili 在 2026-01-20 Midnight 12.0 停更，README 把原因写成 API 新方向无法维持质量。Hekili 源码已有 `IsMidnight`（build >= 120000）。这与本仓库 Secret Values dump 是同一类约束：战斗中生命、能量、光环、冷却、单位身份可能变成 secret，插件不能再当普通数字用。

Forever dump 里这套谓词是完整的，不是空表。

**推断 F2（观察段）：** 零售循环助手那条“读全状态 → 本地模拟 APL”在 Forever 上可能直接不可用。不能默认移植 Hekili。能用的观察必须按字段证伪：哪些返回普通值，哪些是 secret，哪些 NIL。

## 3. 官方下一技能是更薄的观察

`C_AssistedCombat.GetNextCastSpell` 在 wiki 和 Forever dump 同时存在。它返回可空 `spellID`，不提供移动、目标集合或完整状态机。Hekili 死掉的原因，正是官方把“下一技能”收进自己的接口，并收紧第三方状态读取。

**推断 F3（决策段）：** 最小场景应先测 Assisted Combat，而不是移植 SimulationCraft/Hekili。若 `GetNextCastSpell` 在已选目标、战斗中给出稳定非 secret 的 spellID，本地决策可以薄到“把 spellID 对应到键位”。若它不可用或 secret，再考虑自建规则或屏显识别推荐图标。SimC 仍只是离线对照，不进热循环。

## 4. 目标发现不靠敌人列表

dump 和开源都没有“枚举视野内全部敌人”的 API。替代线索已经够拼：

- `TargetNearestEnemy`：选择动作，wiki 与 dump 都在，forever 标注有。
- Soft target：`SoftTargetEnableFlags` 含 `Kbm`；Unit 事件有 `PLAYER_SOFT_ENEMY_CHANGED` / `SOFT_INTERACT_CHANGED`。
- Hekili `Targets.lua`：只用 `target`/`focus`/`bossN`/`arenaN` + nameplate GUID，外加宠物技能探距。这是公开插件在没有敌人列表时的实际做法。
- 本项目最小场景是固定目标，连 nameplate 集合都可以后置。

**推断 F4（目标段）：** 最小场景的目标路径是：软目标或最近敌人为选择，已选目标的 Unit token 为观察。不把 G6 采集枚举失败，解释成战斗目标不可做。

## 5. 出口被 secret 和聊天限制夹住

- SavedVariables 仍是 addon 把表写到磁盘的正路，但 secret 值按设计不能当普通值持久化。
- `AreOutgoingAddonChatMessagesRestricted` 出现在 Forever Chat dump，聊天出口可能比 SV 更窄。
- WeakAuras 的公开能力是屏显，不是给外部程序的数据总线。
- WeakAuras Companion 证明“进程外程序读写插件配置”这一形态存在，但是更新通道，不是战斗热数据。

**推断 F5（出口段）：** 先测“非 secret 标量能否进 SV 并在 reload 后出现”。若关键战斗字段是 secret，SV/聊天都会失败，观察结果只能留在屏上，外部只能像素读推荐图标或状态条。那是观察备援，不是改方向。

## 6. 拼起来的路径（待证伪，不是已实现）

最小场景（固定区域、固定目标、旁观）的技术路径收成：

```text
[游戏内]
  软目标 / 已选 target
  → 只读 addon：限制状态、位置、UnitExists(target)、AssistedCombat.spellID
  → 能写的标量进 SavedVariables；不能写的就画在固定屏位

[进程外]
  读 SV 文件 或 读固定屏位
  → 本地把 spellID/状态映到键
  → SendInput 打已绑定键（移动、最近目标、技能）
```

和公开生态的对应关系：

- 观察：Assisted Combat 或残存 Unit API，不是 Hekili 全量 APL
- 目标：SoftTarget / TargetNearest，不是敌人数组
- 决策：薄映射；SimC/Hekili 仅对照
- 执行：GSE 证明插件内执行走不通，所以执行在进程外
- 备援观察：像素读官方/插件推荐图标，当 secret 切掉结构化出口时启用

明确不纳入实现的对照层：内存、注入、驱动、封包。历史全自动产品多走这一层，本路径不靠它闭合。

## 7. 这批材料改变了什么

相对 `docs/10`：

- 执行必须在进程外：从“选定”升为“有公开约束和开源自述支撑”
- 观察不能默认零售循环插件：Hekili 停更是新的强线索
- Assisted Combat 从“候选 API”升为“最小场景第一观察”
- 目标段有了 SoftTarget 事件和 Hekili nameplate 模式，不再是纯缺口
- 出口在 secret 下可能退化成屏显，这条备援现在有机制理由，不是产品想象

没有改变的：

- 仍无 Forever 真机样本
- dump 名称存在 ≠ 调用成功
- 路径自洽 ≠ 闭环可行
- 合同仍未授权

## 8. 下一步只剩技术物件

1. 只读探针：build、InCombatLockdown、限制事件、位置、`UnitExists("target")`、Assisted Combat 四函数、soft enemy 事件。不施法、不 Interact、不 Move。
2. 把 Hekili/GSE 的架构拆解留在本文件即可，不要把它们的战斗源码搬进仓库当产品。
3. 有客户端后再测 F2/F3/F5；F1 不需要客户端就能从保护函数定性，但效果仍要真机。
