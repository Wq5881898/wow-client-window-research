# 卖灰装与修理装备：这条路径的研究（2026-11-05）

目标：找到能**卖灰色垃圾物品**和**修理装备**的地方，并研究客户端路线能不能走通。

> 同日集中更正：当前仅有小地图移动、光标认名、金钱与占用背包格数的样本；指定商人、商人窗口、卖灰装及修理尚未验证。三处扫描未找到不证明北郡没有商人；用户提示附近商人，旧基线也记载可见商贩，优先核实近处指定对象。需要验证的事项交[任务A1/A2](文档审阅验证任务分工_2026-11-05.md)，下文实测位置与状态均为历史样本。

## 实测结论

1. 当时 `money=0`，不足以支付正价修理；不阻塞开商人窗口、检查耐久或读取报价。当前金钱须重读。
2. 当时 `bags=1` 只表示1个占用格；不知道物品品质、堆叠数或售价，不能推断第一笔收入。
3. 在墓地、草甸、岔路口的扫描未找到商人。撤回“起始区没有、最近在Goldshire”的结论；附近商人按用户提示与旧基线核实，不把跨区远行设为交易前提。
4. 固定方向移动曾在(0.567,0.437)附近受阻，说明该局部方法不足。后续小地图方向与移动已实现，通用绕障和指定目的地到达尚未可靠验证；不能再称导航能力完全没有。
5. **"认出光标下的单位"这条机制已经打通**（v13）：把光标放到一匹马的模型上，
   客户端报出哈希 33001，与 Python 算出的
   `name_hash("Riding White Stallion")` 完全一致 ✓。
   之前扫描找不到名字，是因为网格太粗（110×100 像素）而单位的碰撞框只有
   ~20 像素 —— 机制没问题，是采样密度的问题 ✓。

## 补做：小地图读数（导航的前置）

既然"到不了目的地"是硬门槛，就把小地图读出来：`scripts/client_minimap.py`。

- 小地图**以角色为中心**、**北在上** ✓（画面上确认）→ 标记相对圆心的方向就是世界方向 ✓。
- 标记的颜色实测有两种：任务标记的**饱和黄**（(255,223,0)）与
  蓝灰的**可接任务标记**（(72,81,114)）✓；区域名文字与缩放按钮是别的颜色 ✓，
  用半径 85 像素把它们排除 ✓。
- 朝向换算按客户端的位移公式 `u(θ)=(-sinθ,-cosθ)` 推出 `θ=atan2(-east,-south)` ✓。

**这里发现并修掉了一个符号错误**：第一版写成 `atan2(east,-south)`，
实机表现为**角色朝反方向走**——任务标记在小地图上从 17 像素远跑到 79 像素远 ✓，
轨迹把错误暴露得很清楚 ✓。现在有离线用例锁住"走的位移必须指向标记" ✓。

两张真实小地图存成夹具（`scripts/fixtures/minimap-*.png`），
离线用例覆盖：找到任务标记、排除区域名文字、朝向换算、
以及"按这个朝向走，位移必须指向标记" ✓。

**还没做完**：小地图上**哪个标记是哪个 NPC** 还没法分清（颜色分类只到"黄/蓝"，
玩家的箭头也还没可靠识别）→ 所以"走到任务 NPC/商人那里"这个动作**还不能算可靠**，
只能作为研究结论；下一步是读**大地图**（M 键，标记更大更好认）或先把箭头认准。
