# T1 非控制测量项目

更新：2026-09-23  
性质：候选观测目录，不是阶段 gate 或验收清单。

## 1. 测量对象

T1 这一名称在项目中指不发送游戏控制输入的运行时观察。候选对象包括：

- build 和 addon/限制状态；
- 玩家地图 ID 与位置；
- 玩家手工选择目标后的 Unit 状态；
- Assisted Combat 返回；
- SavedVariables、聊天或屏显等数据路径。

这些对象可以独立取样，不要求按固定阶段顺序完成。

## 2. 记录结构及事实基础

静态 API 名称不能区分调用失败、空值、secret 值、限制事件和真实效果，因此项目现有探针设计使用以下独立字段：

```text
probe_id, sequence, build, scene, monotonic_time,
api, args_shape, call_status, value_status, value_type,
event_status, effect, error_text, note
```

其中：

- `call_status` 记录调用是否返回或报错。
- `value_status` 区分正常值、NIL、SECRET 和不适用。
- `event_status` 记录 Blocked、Forbidden 或限制状态事件。
- `effect` 记录人工观察到的实际效果；纯读取通常为不适用。

这是数据结构说明，不包含成功阈值。

## 3. 候选场景

| 对象 | 手工场景 | 可记录内容 |
|---|---|---|
| 元数据 | 登录后静止 | `GetBuildInfo()`、addon security、限制事件计数 |
| 限制状态 | 非战斗及玩家手工进入战斗 | `C_RestrictedActions`、`InCombatLockdown()`、状态变化 |
| 位置 | 静止及玩家手工移动 | map ID、位置返回、NIL/SECRET/ERROR、时间间隔和抖动 |
| Unit 状态 | 玩家手工选择目标并改变战斗/死亡状态 | 各 API 的调用和值状态、secret predicate、人工场景标签 |
| Assisted Combat | 无目标、选中目标、手工战斗和换目标 | 可用标记、spell ID/列表、NIL/SECRET/ERROR |
| 数据路径 | 人工 reload/退出、聊天候选或屏显 | 发送记录、到达记录、序号、丢失、重复、乱序和延迟 |

表中没有规定样本数。具体次数和持续时间属于实验参数，应随问题、波动和初步结果记录。

## 4. 当前静态依据

- manifest：API `47/47`、事件 `8/8`、枚举假设 `2/3`。
- `C_Map.GetPlayerMapPosition` 在归档文档中存在，返回可空。
- Unit API 存在无条件 secret、条件 secret 和未标同类 guard 的不同表面。
- Assisted Combat 三个主要读取候选在归档中存在。
- 聊天 API 带限制标记；SavedVariables 的实时持久化尚未观察；屏显读取方式尚未测试。

## 5. 工程保护

探针实现中的下列行为用于防止仪器自身产生不可控结果：

- 原始记录追加保存，统计由原始记录生成。
- 不把 secret 值用于算术、比较、索引或持久化。
- 不记录账号、角色、服务器、设备或联系人标识。
- 出现持续输出、客户端异常或仪器错误时终止该次采集，以免继续污染记录。

这些是仪器完整性和数据最小化约束，不是技术路线的 go/no-go 规则。
