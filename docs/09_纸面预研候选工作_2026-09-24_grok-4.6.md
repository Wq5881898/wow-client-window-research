# 纸面预研候选工作

文件：`docs/09_纸面预研候选工作_2026-09-24_grok-4.6.md`  
日期：2026-09-24  
作者：grok-4.6  
性质：真机条件不具备时的候选工作清单。不是阶段 gate、不是验收门槛、不是用户决定、不是授权判断。  
后续修订另存为 `docs/09_纸面预研候选工作_<日期>_<模型>.md`，不覆盖本文件。

本清单不恢复 T0–T3/D1、`99%`、`p95 <= 500 ms`、`30/30`、产品 B/W1 主线或 15C 阻塞。不把 API 存在、仿真输出或历史材料写成真机证明。

## 1. 当前状态

仍是预研。纸面部分已经校准完，真机部分尚未开始。

用户已确认：真机预研暂不具备条件，现在只能纸面预研。这是条件陈述，不是把纸面工作升格为可行性证明。

纸面还能增加的信息有限。有价值的工作是：把已有假设写成可证伪账本、冻结静态语料、准备可加载但不在本机加载的只读探针源码。没有价值的工作是：继续扩写同一套可行性结论、加大合成仿真、重测在线端点、恢复访谈或产品路线。

真机所需而尚未由用户决定的事项保持开放：测试机、客户端 build、第一项真机观察范围、是否研究更高风险操作实现、是否发布。

## 2. 纸面做得到和做不到

### 2.1 做得到

- 把最小场景所需能力写成独立、可证伪假设。
- 核对归档 dump 是否钉死，补静态扫描缺口。
- 写出只读探针源码和记录契约，本机不加载。
- 分开描述 SavedVariables / 聊天 / 屏显三条出口的静态依据与未知项。
- 监测公开页面是否出现 Forever 专项条款或 dump 更新。
- 择机做仓库卫生，不增加技术可行性证据。

### 2.2 做不到

- 证明位置、Unit、Assisted Combat 真机可读。
- 证明外部输入有游戏效果。
- 证明或否定闭环。
- 测量当前反作弊或处罚概率。
- 检查客户端安装/登录附加条款。
- 取得 Blizzard 授权或法律结论。

纸面工作结束的标志不是“可行性通过”，而是：假设账本可交给真机、只读探针源码可带到测试机、静态语料可复查。之后若仍无测试机，应停止扩写，而不是再开一轮综述。

## 3. 最小场景假设账本

讨论过的最小场景：普通开放世界、固定区域、固定目标、全程旁观。它不是最终产品范围。下表是工作假设，不是已证实能力。

| ID | 假设 | 现有依据类型 | 纸面可做 | 真机才能做 | 失败时只否定 |
|---|---|---|---|---|---|
| H1 | 目标客户端可记录 build 与 addon/限制状态 | 文档化表面：`GetBuildInfo`、`C_AddOns`、`C_RestrictedActions` | 写只读探针字段 | 对照归档镜像 | 该 build 的元数据记录法 |
| H2 | 玩家/队友地图坐标是固定区域场景的可用输入 | 文档化表面：`C_Map.GetPlayerMapPosition` 可空、限 player/party | 列 NIL/SECRET/ERROR 记录规则 | 静止与手工移动取样 | 该 API 作为位置来源 |
| H3 | 玩家手工选定目标后，部分 Unit 状态可形成能力矩阵 | 文档化表面：Unit 与 `C_Secrets` 分档；不是完整状态机 | 按 API 列出待测 token/场景 | 分列 call/value/event | 被测 API+token+场景组合 |
| H4 | 固定目标可降低敌人集合需求，但不能取消目标失效/额外敌人问题 | 工作假设；`TargetNearestEnemy` 只是动作表面 | 列出失效/ADD 的替代观察候选 | 目标死亡、消失、ADD 时取样 | “固定目标等于零感知” |
| H5 | Assisted Combat 可能减少循环维护，不是移动/目标/输入方案 | 文档化表面：三个读取候选 | 列无目标/有目标/换目标记录项 | 记录返回形态 | 把它当完整战斗模块 |
| H6 | 观察结果需要一条到达外部程序的路径 | 机制资料：SavedVariables、聊天、屏显 | 三条路径分开写契约 | 到达、丢失、延迟、乱序 | 某一条路径 |
| H7 | 标准输入可能把单键送入游戏 | 仪器 dry-run 与 ABI；无真实发送 | 只保留现有仪器说明 | 用户决定范围后才考虑 | 该发送通道 |
| H8 | 采集不是当前最小场景的必要项 | G6 四枚举成员静态失败；另有拾取/容器表面 | 不把采集写回主线 | 若以后单独研究再测 | 旧枚举方案（已失败） |

H7 在纸面阶段不实施、不解锁 live、不向任何窗口发送。H8 维持现状：采集观察仍可作非主线静态备注，不进入最小场景必测项。

闭环（移动、战斗、恢复）不是独立纸面证明对象。它依赖 H1–H7 的真机结果，纸面只保留“组成闭环所需的最小观察集合未知”。

## 4. 候选工作项

各项独立。没有必须完成的顺序，也没有“做完一项才能做下一项”。

### P1. 把假设账本落成可执行对照表

产出：一份只含 H1–H8 的对照表，每行有：静态出处路径、拟用 `probe_id`、手工场景、四维字段、身份字段禁写规则。

不要把对照表写成验收清单。不要补样本数、通过率或时长门槛。

### P2. 编写只读探针源码，本机不加载

产出：可带到测试机的 addon 草稿，覆盖 H1–H5 的读取与记录，不包含攻击、移动、宏循环或自动选目标。

约束：

- 使用现有四维记录模型。
- secret 值不进入算术、比较、索引或持久化。
- 不记录账号、角色、服务器、设备或联系人。
- 内存赋值与文件持久化分开写。
- 源码进仓库不等于已在客户端运行。

这是纸面阶段信息量最高的工程项。它不产生真机证据。

### P3. 冻结静态 API 语料

产出：`sources/forever_dumps/` 的文件清单、字节数、SHA-256，以及归档时所依据的第三方镜像说明。现有 lint 只证明名称匹配，不证明语料以后不会被重新下载覆盖。

可顺带做一次只读缺口扫描：软目标、nameplate、mouseover、interact、尸体、坐骑/移动相关文档是否还在 dump 中、是否已被附录覆盖。扫描结果仍是文档化表面。

不要为了“再确认一次 47/47”而重复 lint 当进度。

### P4. 数据出口的纸面契约

产出：SavedVariables、聊天、屏显三条路径各写一页：静态依据、未知项、若真机测试应分列的字段。三者不得合并成“数据路径可用”。

聊天路径须单独标注限制标记和隐私风险；纸面阶段不设计向公共频道发信的方案。

### P5. 公开来源监测，非 15C 等待

产出：若公开 EULA 修订日期、Legal 索引或 Forever 公告出现新条款链接，则追加取证记录。这不阻塞个人实验，也不代替客户端安装流程检查。

客户端内附加条款仍然只有安装后才能看。纸面监测填的是公开网页缺口，不是授权缺口。

### P6. 仓库卫生（可选，不增加可行性证据）

仅在不动研究结论时处理：

- 修正 T2 dry-run 的 `records` / `summary` 契约，使文档与 JSON 一致。
- 给 `lat.py`、`lat2.py`、`lat3.py`、`audit.py`、`w3.py`、`w4.py` 加历史仪器说明，避免被当成当前运行配置。
- 避免 `audit*.py` 覆盖已归档 dump。
- 统一附录日期戳。

这些项可做可不做。做完也不改变“真机证据为零”。

## 5. 纸面阶段停止做的事

- 再写一份与主报告同结论的可行性综述。
- 扩大 `bot_sim.py` 世界、职业或云策略，并把它当作验证。
- 把在线端点再测一轮当作控制问题的进展。
- 恢复 W1、产品 B，或把产品失败解释为视觉架构成立。
- 向编辑器、游戏或其他窗口发送真实输入。
- 把高风险技术从非操作性讨论推进到操作实现。
- 为发布、分发、商业化起草执行方案。

合成模型保持 v4 即可。需要时只修回归，不靠加场景证明 Forever。

## 6. 条件变化时如何交接，不是开关卡

若用户之后提供测试机和客户端，纸面清单让位给只读真机观察。建议的第一批真机对象仍是独立取样，不是关卡：

1. build 与限制状态（H1）
2. 玩家位置（H2）
3. 手工选中目标后的 Unit 状态（H3）
4. Assisted Combat 返回（H5）

数据出口（H6）可与上列并行。真实输入（H7）仍须用户另行指定范围后才考虑。采集（H8）不进入最小场景第一批。

真机开始不要求本清单 P1–P6 全部完成。有测试机时，未完成的纸面项变成可选。

## 7. 建议的纸面执行顺序（仅降低返工，不是 gate）

若继续做，返工最少的顺序是：

1. P1 假设对照表  
2. P2 只读探针草稿  
3. P3 语料冻结  
4. P4 出口契约  
5. P5 有公开变更才追加  
6. P6 有空再做  

停在 P1+P2 已经够把纸面预研收口。P3 值得做，因为它保护现有证据。P4–P6 是增益项。

## 8. 本文件不决定的事

- 何时取得测试机。
- 第一项真机观察的具体范围。
- 是否编写或加载探针以外的任何控制代码。
- 是否进行更高风险技术的操作实现。
- 是否恢复访谈或任何产品方向。
- 是否发布或商业化。

这些仍以 `docs/03_决策后工作计划.md` 为准。
