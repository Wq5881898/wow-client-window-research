## ACT-01：输入发出但角色没反应

**状态**：LOCAL-RUN历史输入缺陷；**2026-11-06 实机标定两个常数**（见[本轮记录](../客户端实机基线与驱动修复_2026-11-06.md)）：**转向速率 2.66 rad/s**（四次半秒转向：2.702/2.613/2.660/2.791），不是 π —— 用 π 算会让每次转向过冲；**移动键位非标准**：W 完全不动，A/D/S 与方向键才有位移。常数在 `scripts/client_motion.py`，五个使用点统一引用。当前动作须核后置条件。

先查实际绑定和输入路径，再查战斗策略：

1. 输入前焦点属于哪个窗口；隐藏cmd不证明游戏取得焦点。
2. 聊天输入、世界地图、菜单和当前世界界面是否一致；读取失败不视为聊天已关闭。
3. 用的是SendInput、WM_CHAR还是PostMessage按键；历史结果随窗口模式变化，不能概括某接口永远有效或无效。
4. 核实际键义：本机A曾是侧移，方向键才转向；SendInput返回成功不证明应用执行。
   **2026-11-06 补充：W 在本机不产生位移**；判断"有没有动"要用探针位置读数
   （量化步长约 0.0000458），不要用按键的返回值。
5. 动作按下/释放必须配对；失败也要释放。没有可靠焦点时，不以盲发更多键补救。
6. **发送成功不等于应用执行**：本机实测聊天能把命令送到服务器
   （收到 "You can't chat when you're dead!"），而同一时刻世界里的移动键无效。

**成熟参照**：S01读取实际游戏绑定并传到外部按键层；本库建议借鉴“读绑定与确认效果”。其插件自动写绑定的部分不符合当前只读探针约定。

**最小验证**：安全场景一次有界按键，记录输入前后窗口/聊天状态、绑定、位置/朝向/事件。先复用既有原语，不新造一套输入函数。

**本地入口**：`scripts/lab_driver5.py`、`client_chat_guard.py`、`client_geometry.py`；[输入缺陷历史](../客户端输入通道缺陷_2026-11-02.md)。

## ACT-02：施法慢、聊天命令不稳定或技能判断错误

**状态**：LOCAL-RUN 本机法术表已用客户端自身的 GetSpellInfo 核对（旧表有误）；SOURCE-CODE成熟参照；动作条改造属PROPOSAL；见[验证记录](../客户端审阅验证回报_2026-11-05.md)
**本机法术表（3.3.5a build 12340；探针用客户端自己的 GetSpellInfo 自报，画面证据见验证记录）**

| ID | 客户端给出的名称 | 施法时间 |
| --- | --- | --- |
| 116 | Frostbolt | 1.20 秒 |
| 120 | Cone of Cold | 1 秒 |
| 122 | Frost Nova | 1 秒 |
| 123 | 不存在 | — |
| 133 | Fireball | 1 秒 |
| 168 | Frost Armor | 1 秒 |
| 212 | 不存在 | — |
| 213 | 不存在 | — |

结论：**旧表把 116 写成 Frost Nova、122 写成 Frost Shock、123 写成 Frostbolt 是错的**；本机的对应是 116=Frostbolt、120=Cone of Cold、122=Frost Nova、133=Fireball，而 123/212/213 在本机根本不存在。**Frostbolt 不是瞬发，施法 1.20 秒**，所以"寒冰箭不是默认瞬发"由本机数据证实。按名字查已学不能区分同名不同等级；驱动应以 spell_bits（已学位图）与客户端自己的 GetSpellInfo 为准，不要以名称推定。

优先使用安全阶段已核对的动作条按键。一次常规战斗动作不必重复经历开聊天、逐字符、提交和固定等待。聊天保留必要诊断/配置；每次按键后按事件和目标状态推进。

开战前记录：法术ID、名称、等级、已学状态、动作条槽位与绑定、资源、目标GUID。GetSpellInfo可给未学法术名称，按名字比对也不能可靠区分同名等级。

**已知更正**：116为Frostbolt，122为Frost Nova，120为Cone of Cold；旧123/213/212标签不可作当前依据。寒冰箭通常有施法时间。完整ID/等级仍以本机法术书与版本匹配资料核对。

**最小验证**：同一安全非战斗法术对照动作条输入与旧入口，记录从发键到新事件的时间、实际增益/资源变化与采样空窗；非战斗通过不代替攻击验证。

**完成判据**：正确法术执行且事件为本次新增，重复运行不残留聊天，取消后不继续提交旧命令。

**本地入口**：`WowProbeLive.lua`法术候选、`scripts/lab_client_combat_loop.py`、`client_chat_sequence.py`；[法术表更正](../客户端协议v6与v7_2026-11-02.md)。S01参照 `SetupDefaultBindings.lua`、`CastingHandler`。

## ACT-03：SUCCEEDED但不掉血、回血或朝向/射程问题

**状态**：LOCAL-RUN净血量观测；抗性/逃跑/回血原因待核；**SUCCEEDED 不再等价于命中**（成功计数按本次战斗的 serial 去重，见[验证记录](../客户端审阅验证回报_2026-11-05.md)；SOURCE-CODE参照S01。

分别确认“施法成功”“实际伤害”“目标变化”“目标回血”。SUCCEEDED不证明命中；小净掉血可能混有伤害、抵抗、吸收、回血或不同采样时刻。玩家combat=False不证明目标未进战。

排查顺序：同GUID及新事件→射程与即时错误→法术/目标等级与资源→伤害/吸收/抵抗/回血事件→目标分类及服务端规则。range错误不是伤害日志中的miss；facing、range、LOS可能按客户端校验顺序先后出现。

**最小验证**：一个明确目标、一种法术、有限尝试，记录带时间的目标生命与可取得的逐事件信息；按来伤和资源进入既定恢复分支，不能战斗中停下来reload取证。

**完成判据**：原因与具体证据相符；无法排除其他解释就记录未知，不把“精英”直接写成高抗性根因。回血重试需要总次数、总时限和无进展预算。

**本地入口**：`scripts/client_combat_controller.py`、`client_facing.py`；[旧机理更正](../客户端战斗回血机制与选目标约束_2026-11-01.md)。

## CTL-01：低血/失联后没有及时恢复，或动作无法中断

**状态**：LOCAL-OFFLINE 修复已实现并有反例（reader 异常转入恢复分支、施法在途检查低血/死亡/目标身份）；**2026-11-06 补齐取消链路**：检查的返回值不再被丢弃，输入线程可停止、按键可立即释放，TURN 扫描与接近阶段接入同一守卫，理由被锁存（`scripts/client_action_guard.py`）；**实机故障注入仍未做**，最终状态查[验证记录](../客户端审阅验证回报_2026-11-05.md)与[本轮记录](../客户端闭环修复与执行验证_2026-11-06.md)。SOURCE-CODE参照S01的InterruptWatchdog。

统一控制链应为：读帧→解码/新鲜度→生命与身份判定→动作许可或取消→恢复→后置条件。reader异常必须进入故障管理；放在reader之后的window_visible分支覆盖不了先抛错的路径。

持续采样与可中断控制是两个能力：heartbeat只推进心跳，不自动检查低血；后台施法线程也必须可停止后续输入。TURN内多次试施法必须受同一资源、生命、身份、次数和总时间预算约束。

**最小反例集**：动作中低血；面板消失；旧帧不前进；目标换GUID；施法线程尚未提交时取消；回血与rebind重复重置预算。用真实入口或可替换reader回放验证，不能只测纯状态机。

**完成判据**：拒绝后不再发不适当动作；输入释放；有明确恢复路径或“无法确认恢复”的结果。会话不可用时不宣称已经安全撤离。

**本地入口**：`scripts/client_control_guard.py`、`client_combat_controller.py`、`lab_client_combat_loop.py`、`client_retreat.py`、`client_action_guard.py`；[死亡复盘](../客户端施法与战斗失败复盘_2026-10-29.md)。
