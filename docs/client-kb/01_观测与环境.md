## OBS-01：黑屏、冻结或找不到客户端

**状态**：LOCAL-RUN历史故障；**2026-11-06 实机确认四条环境事实**（见[本轮记录](../客户端实机基线与驱动修复_2026-11-06.md)）。适用：本机Windows交互桌面与3.3.5a。

- agent 的 shell 在 **session 0**（服务），客户端在 **session 1**（console）。
  session 0 里抓屏得到黑图、输入发不出去。
- **只有 `schtasks /create … /it /ru <用户>` 建的任务会跑在 session 1**；
  `Register-ScheduledTask -LogonType Interactive` 从 session 0 启动时仍落在 session 0。
- 任务进程还要**切到交互桌面**（`SetProcessWindowStation('WinSta0')` +
  `SetThreadDesktop('Default')`），否则 `SetCursorPos` 直接失败。该切换已放进
  `scripts/lab_driver5.py`，所有驱动脚本导入时自动执行。
- **桌面与用户共用**：前台可能是别的程序（实测是 Chrome），读数会变成那个
  程序的画面。读数前要用 `d.restore_foreground` 确认客户端在前台。
- **跨会话重建存活下来的旧客户端会把输入卡死**：`SetCursorPos` 与
  `SendInput` 全部无效、键盘不响应；重启客户端后立刻恢复。症状像驱动坏了，
  实则是客户端进程的问题。

先记录操作发生在哪个会话、客户端进程属于哪个会话、窗口是否存在、当前界面和抓屏来源。Session 0查不到用户会话窗口，不证明游戏退出；有进程也不证明已经进世界。

排查顺序：

1. 对照进程、会话、窗口与截图；截图黑屏时优先核会话是否渲染、锁屏或断开。
2. 读可见错误框。RDP启动拒绝有直接历史弹窗证据；不要先推断硬件损坏。
3. 在游戏所在交互会话使用现有 `client_capture.grab_desktop()` 核对；观察者会话抓到的旧画面不能当实时状态。
4. 用登录/角色选择/游戏世界的界面特征定位阶段，再检查探针。登录画面没有探针，不能用“读不到就按ESC”恢复，因为该画面ESC会退出客户端。
5. 若进程退出，记录退出时间和相邻日志。Kernel-Power 566的系统会话字段尚未证实等于Windows登录会话，相关性不等于根因。

**最小验证**：安全状态下，同一时刻记录会话/进程/窗口/截图四者，确认哪个环节首次丢失；不为诊断同时启动第二个客户端驱动。

**完成判据**：实际界面与新鲜观测一致；能够区分未启动、未渲染、未进世界、探针失效。恢复登录不等于原任务完成。

**本地入口**：`scripts/client_capture.py`、`client_window_state.py`、`client_read_fresh.py`、`lab_client_restart.py`；[手册](../客户端实验指导手册.md)；[来源L01/L03](06_来源目录.md#local)。

## OBS-02：色块有显示，但telemetry absent或校验失败

**状态**：LOCAL-RUN / LOCAL-OFFLINE；SOURCE-CODE参照S01。关键词：版本、长度、尾标、像素偏移、UI缩放、gamma、Lua错误。

按以下层次排查：

1. 截图中的色块是否真实可见、未被菜单/地图/其他窗口覆盖。
2. Lua是否持续报错；历史 `UnitClassification` 字符串交给 `math.floor` 导致目标一出现就停止更新。
3. 实际部署协议版本、声明长度、Lua字段顺序、Python偏移和尾标搜索是否一致。
4. 实际客户区位置、屏幕分辨率、UI缩放、色块步距是否与配置一致。
5. 对已保存失败截图离线解码。相同图修正几何后可解码支持定位/布局原因，仍需新run复验实时链路。

**成熟参照**：S01有独立FrameConfig/配置过程；issue704记录3.3.5移植时的UI边界、色块取整与像素偏移。作者建议不等于本机参数，不直接复制其1px或3px色块尺寸。

**最小验证**：一张失败原图＋实际协议/窗口尺寸＋离线解码错误分类。仅在相关配置变化时重做标定。

**完成判据**：完整帧校验通过且序号/游戏时间连续推进；不是只看到一帧可解码。发布代码与部署副本版本必须能对应。

**本地入口**：`probes/WowProbeWotLK/WowProbeLive.lua`、`scripts/client_live_layout.py`、`client_live_state.py`、`test_client_live_layout.py`；[协议历史](../客户端协议v8与v9_2026-11-05.md)。

## OBS-03：观测陈旧、遮挡或采集太慢

**状态**：本地已有Freshness与部分实测，SOURCE-DOC / SOURCE-CODE参照S01；WGC/DXGI替换属PROPOSAL。

先分开量截图、解码、等待、动作输入耗时，记录最大相邻观测间隔。不要把脚本总耗时都归给截图，也不要把0.1秒面板更新等同0.1秒端到端延迟。

成熟项目把插件区域与完整画面分开处理，提供DXGI桌面复制与WGC窗口采集。WGC捕获被其他窗口遮挡的游戏画面是作者支持环境中的能力，不保证最小化、会话断开、虚拟显示和本机旧D3D9都可用；可后台采图也不等于后台键盘输入有效。

**最小比较**：同一安全场景、相同面板和分辨率，比较现有BitBlt、真正局部采集、候选WGC/DXGI。分别记录前台、遮挡、失焦的有效帧率/最大间隔/处理耗时及失败原因。全屏抓完再裁剪只节省后续处理，不自动节省抓屏成本。

**新鲜度规则**：序号与游戏时间一起检查；重载/重启须重建明确基线。已知动作耗时不能成为忽略战斗期观测空窗的理由。读取失败应进入[CTL-01](02_输入与战斗.md#ctl-01)，不能当“聊天已关/玩家安全”。

**完成判据**：异常时拒绝旧帧、有效采集能贯穿动作、失败可进入恢复管理；选择后端以本机对照数据为准。

**本地入口**：`scripts/client_live_state.py`的Freshness、`client_capture.py`；[连续观测样本](../客户端输入期间连续观测_2026-10-30.md)。
