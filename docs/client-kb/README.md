## 查询方法

正在战斗或移动时，由现有驱动持续控制与恢复；本库的人工排障和离线取证应在安全收尾后进行，不把阅读文档或等待诊断插入战斗控制链。

先按现象找到编号，再依次核对：适用环境→直接可见事实→候选原因→最小区分实验→后置条件。问题仍未解决时，把新证据写成[验证记录](07_验证记录与维护.md)，而不是先增加一个新的泛化结论。

支持编辑器全文搜索；PowerShell可用：

```powershell
# 在项目根目录执行；只搜索文档，不运行客户端
Select-String -Path "docs/client-kb/*.md" -Encoding UTF8 -Pattern "NPC-01|商人|Interact"
```

如果终端输出中文仍乱码，这是控制台输出编码问题，不代表文件损坏。可用编辑器，或使用下面已核对的UTF-8查询入口：

```powershell
python -B -X utf8 scripts/client_kb_check.py --find "商人"
python -B -X utf8 scripts/client_kb_check.py --find "ACC-01"
```

该查询只匹配索引中的编号/关键词，忽略英文大小写；空格或`|`分隔的词按“或”匹配，不做自然语言推理。无命中返回码2，建议缩短关键词或全文搜索主题文件；检查成功/查询命中返回码0。

固定问题编号作为搜索主键；增加条目时保留已有编号。目录锚点使用显式ASCII编号，便于链接。

### 一分钟内选对第一步

| 你遇到的情况 | 先查 | 第一项区分检查 |
| --- | --- | --- |
| 角色不动、输入成功却没效果 | ACT-01；若整幅画面不更新再查OBS-01 | 焦点、聊天框和真实键义，不先改导航参数 |
| 有色块但报telemetry absent | OBS-02；若旧帧可读但不前进查OBS-03 | 对一张失败原图核协议/几何，区别解码错误与新鲜度拒绝 |
| 找到守卫，还是没找到商人 | NPC-01 | 候选是不是指定商人，不能把任意名字当任务完成 |
| bag_items变少，是否卖成功 | TXN-01 | 对应物品ID/品质/堆叠与金钱，格数变化只是旁证 |
| 复活且重登正常，却没有撤回墓地 | REC-01 | 锚点来自释放后的墓地，还是释放前尸体位置 |
| 测试全绿但实机结果不对 | ACC-01/ACC-02 | 反例能否拒绝假成功；报告是否绑定本次实际任务 |
| 想直接安装成熟框架 | VER-01 | 3.3.5原版与3.4.x怀旧是否被混同 |

文档渲染器若不支持锚点跳转，打开表中主题文件并全文搜索问题编号即可；无需依赖HTML锚点才能查询。[本地代码入口](06_来源目录.md#code)提供可点击文件链接。

### 检查知识库本身

```powershell
python -B -X utf8 scripts/client_kb_check.py
```

只读检查问题编号、索引、锚点、全部本地链接与项目入口；不会联网或导入游戏驱动。通过不代表外网可达、故障已修复或实机任务通过。

## 证据状态怎么读

| 标签 | 含义 | 不能替代什么 |
| --- | --- | --- |
| LOCAL-RUN | 有本地实机历史样本 | 当前角色状态、跨版本可靠性 |
| LOCAL-OFFLINE | 代码/状态序列/离线反例确认 | 实机动作效果 |
| SOURCE-CODE | 已读指定版本源码 | 本机安装、构建、兼容和运行成功 |
| SOURCE-DOC | 已读作者文档或评论 | 独立复现或本机验证 |
| PROPOSAL | 建议的最小验证/改进 | 已实现、已通过 |
| SUPERSEDED | 旧解释已更正 | 删除失败记录或改写原始证据 |

每个条目列出的状态只覆盖注明的事实；“问题曾确认”不等于“当前代码仍未修”。已有两份验证报告入账（见[验证账本](07_验证记录与维护.md#已纳入的验证报告)）：判据类缺陷在**离线层面**已修复并有反例，**实机复测仍未做**，条目按此回填。[任务分工与接收状态](../文档审阅验证任务分工_2026-11-05.md)记录工作安排，不是验证报告。
