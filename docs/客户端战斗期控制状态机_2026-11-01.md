# 客户端战斗期控制状态机

## 结果

`results/client_controller_1793508935719320300.json`：
`CONTROLLER_SELF_BINDING_VERIFIED`。

实机确认两件事：

1. 绑定**自身**目标（GUID `0x0000000000000008`）被拒绝，理由 `target_not_attackable`，
   连续6帧保持拒绝。
2. 把同一状态的 `target_attackable` 置真后，同一状态机放行：
   `CAST_ALLOWED`，尝试计数1。

全程非战斗，没有攻击任何生物，没有施法伤害。

## 状态机决策

`client_combat_controller.py`是纯判定层，不发送任何输入。

| 决策 | 触发条件 | 含义 |
| --- | --- | --- |
| `BOUND` | 目标GUID一致、可攻击、存活、有生命 | 目标已确认，可以进入战斗流程 |
| `CAST_ALLOWED` | 目标确认 + 心跳新鲜 + 射程明确为1 + 已学 + 无失败事件 | 允许驱动发起一次施法 |
| `CLOSE_DISTANCE` | 射程为0，或失败原因为射程/朝向/视线 | 需要靠近，不是失败 |
| `WAIT` | 正在施法，或失败原因为法力/冷却 | 等待即可 |
| `VERIFY_SURVIVAL` | 目标已死亡 | 仍需确认玩家存活且脱战 |
| `RECOVER` | 玩家死亡、低血、目标丢失或换人、窗口不可见、观测陈旧、法力/冷却类以外的目标无效、尝试次数用尽 | 必须走恢复分支 |

关键约束：

- **目标身份全程绑定**。目标GUID在战斗开始后任何时刻不一致、消失或换人，
  都直接进入恢复，不允许"对新目标继续施法"。
- **恢复是锁存的**。一旦进入 `RECOVER`，后续正常帧不会自动解除。
- **失败事件不重复消费**。同一失败事件只触发一次分支，不会每帧重复触发。
- **尝试次数有上限**（默认4次），用尽后强制恢复，不允许无限施法。
- **目标剩3生命不算成功**，仍返回 `CAST_ALLOWED`。
- **目标死亡不等于任务结束**，必须转入 `VERIFY_SURVIVAL`。

## 低血阈值

70%生命触发恢复。这是设计值，**未针对真实来伤速率验证**。
角色最大生命52，70%对应约36血。阈值是否足够必须实测后才能定。
