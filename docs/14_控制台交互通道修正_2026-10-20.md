## 二、本会话新发现

### 2.1 `ensure_foreground` 曾把游戏最小化
`lab_driver5.ensure_foreground` 对游戏窗口执行 `SetWindowPos(...1200x800)`。
D3D9 客户端在窗口尺寸被外部改变时会进入最小化（窗口 rect 变为 `-32000,-32000`，client 160x28），
导致后续所有输入落到错误目标、Enter 看似"被吞"。
**修正**：对类名 `GxWindowClassD3d` 的窗口只 `SetForegroundWindow`，不 `SetWindowPos`。
佐证：窗口恢复后，同样的 `/run` 注入立即生效（`ALIVE3` 红字出现）。

### 2.2 误按 Esc 打开游戏菜单后的恢复手段
- `ReturnToGame()` 在菜单打开时**不生效**（3.3.5a 行为）。
- `RunMacroText("/click ...")` 对 Blizzard 框架按钮一律被拦截：
  弹 "A macro script has been blocked from an action only available to the Blizzard UI."
- **可靠做法**：聊天框输入 `/click GameMenuFrame`（聊天触发的 `/click` 不受限），
  或直接 `GameMenuFrame:Hide()`（`/run GameMenuFrame:Hide()` 实测有效）。
- StaticPopup 弹窗（含上述 blocked 弹窗）可用
  `/run StaticPopup1.button1:Click()` 关闭——`/click` 在宏通道被拦，但 Lua `:Click()` 有效。

### 2.3 本实验环境 AddOn 对 Blizzard 按钮的限制清单
| 手段 | 结果 |
|---|---|
| `/click BUTTON`（聊天触发） | 允许（如 `/click GameMenuFrame` 成功） |
| `RunMacroText("/click ...")` | 被拦截（Blizzard-UI-only 动作） |
| `StaticPopup1.button1:Click()` | 允许 |
| `GameMenuFrame:GetChildren()` | 返回 0（菜单按钮是匿名/隐藏子对象，无法枚举点击） |
