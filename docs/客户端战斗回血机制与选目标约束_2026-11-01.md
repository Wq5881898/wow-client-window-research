# 客户端战斗回血机制与选目标约束

## 核心发现：脱战快速回血

`results/client_damage_trace_*.json` 用密集采样（每 0.25 秒）记录了一次火球术
之后目标血量的完整变化：

| 时刻 | 目标 GUID | 血量 | combat |
|---|---|---|---|
| 0.21 s | 0xF130000071000D49 | 120 | False |
| 2.00 s | 0xF130000071000D49 | 120 | False |
| 2.91 s | 0xF130000071000D49 | **99** | False |
| 3.82 s | 0xF130000071000D49 | 99 | False |
| 4.27 s | 0xF130000071000D49 | **120** | False |
| 6.08 s | 0xF130000071000D49 | 120 | False |
| 7.46 s | 0xF130000071000D49 | 119 | False |

三点结论：

1. **GUID 全程不变**，所以血量回升不是换了目标。
2. **21 点伤害在约 0.5 秒内被完全回满**。
3. **角色的 `combat` 始终为 false**，即目标从未真正进入战斗状态。

这是服务端的**脱战快速回血**规则：生物离开战斗后迅速恢复生命值。

## 为什么慢速法术打不死高血目标

火球术的施法时间是 2.5 秒，`results/client_cast_gap_*.json` 实测：

- 命令发出到 `cast_started`：0.448 秒
- 第二次施法要等 8.089 秒才观察到 `cast_started` 变化——因为**上一发还没结束**

也就是说**两次火球术之间必然有超过 1 秒的空闲**，而回血只需 0.5 秒。
一发火球 21 点伤害，目标 120 血时，无论打多少发都会在两发之间回满。

这解释了此前战斗闭环里看到的血量序列
`120 → 103 → 119 → 120`：**每一发的伤害都真实命中，但都被回血抵消了**。

### 与 2026-10-29 那次成功的差异

Probehuman 当年用 3 发火球术打死了 42 血的 1 级狼，没有出现回血抵消。
差异在两点：

| | 1 级狼（42 血） | 石崖野猪（120 血） |
| --- | --- | --- |
| 目标等级 | 1 | 6 |
| 逃跑行为 | 不会跑 | 会跑出战斗 |
| 需要的施法次数 | 3 发 | 6 发以上 |

**低等级、不会逃跑的目标**即使血量高于单发伤害，也能在回血前被打死；
会逃跑的高等级目标则不行。

## 由此得出的选目标约束

`lab_client_combat_loop.py` 与 `lab_client_hunt.py` 现在都会拒绝
**血量超过 70** 的目标：

```python
MAX_TARGET_HEALTH = 70
```

理由是慢速法术无法在目标回血前把它打死。这个阈值是按
「单发伤害 21 点 × 3 发 = 63 点」推出来的保守值，
覆盖了 Probehuman 时期验证过的 42 血目标。

## 控制器新增回血检测

`client_combat_controller.py` 现在会观察绑定目标的健康值：

- 绑定时记录基线，避免第一帧被误判成回血；
- 之后每次观测到**血量上升**，就判定目标脱战回血，把尝试次数预算清零
  并重新开打，而不是耗尽预算后失败。

新增 `recoveries` 计数与 5 项离线测试（`test_client_target_recovery.py`）。

## 战斗闭环接入朝向 sweep

`lab_client_combat_loop.py` 的 `TURN` 分支原先只转 10° 就继续循环，
等于每次失败只试一个角度。现在改为调用已验证的 `sweep_toward`：
**每转一小步就再施法一次，直到施法成功**。

同时战斗闭环新增：

- 用 Tab 键选取敌对目标（不依赖已知的生物名字）；
- 施法前的接近步骤（Tab 转向 + 前进，直到 `spell_range == 1`）；
- 协议检查从「必须是 v4」放宽为「v4 或 v5」。

## 实机结果

`results/client_combat_1793548837949906300.json`：闭环完整跑通，
接近 → 施法 4 次 → 目标掉血 → 尝试预算耗尽 → 恢复分支脱战，
最终 `health 142, combat False, dead False`。

其中目标掉血 `120 → 103` 真实命中，随后 `→ 119 → 120` 是回血抵消，
与上面的诊断完全一致。

## 新增工具

| 脚本 | 作用 |
| --- | --- |
| `scripts/lab_client_damage_trace.py` | 密集采样目标血量，区分回血、换目标与复活 |
| `scripts/lab_client_cast_gap.py` | 测量连续施法的最小间隔 |
| `scripts/lab_client_regen.py` | 静置观察目标血量是否自行恢复 |
| `scripts/lab_client_target_identity.py` | 验证 Tab 切换目标时 GUID 是否变化 |
| `scripts/lab_client_spell_check.py` | 逐个测试角色会哪些法术 |
| `scripts/lab_client_enter_character.py` | 从登录/选人/世界任一状态进入指定角色 |

`lab_client_enter_character.py` 现在用红色像素检测选人界面的 Enter World 按钮，
以区分登录界面与角色选择界面，因此可以从任何界面状态进入世界。

## 仍未验证

- **瞬发法术（寒冰箭）能否解决回血问题**。Syra 是否会寒冰箭尚未测出：
  实测环境里一度找不到视野内的敌对目标，测试没有完成。若寒冰箭可用，
  瞬发特性可以把施法间隔压到 1 秒以内，持续压制目标不让它脱战。
- **控制类法术**（冰冻新星、霜甲）同样未测。冻结目标可以从根本上阻止
  它逃跑和脱战回血。
- 血量上限 70 只是按伤害推算的保守值，没有针对不同等级的目标标定。
- 客户端在本轮多次自行回到登录界面（服务器空闲踢人或连接断开），
  尚未定位原因。这让长链条的实机验证很不稳定。
