## 逐条实际结果

1. **OBS-01 运行环境（实机确认）**
   - agent 的 shell 在 **session 0**（服务），客户端在 **session 1**（console，qrz）。
     session 0 里抓屏得到黑图、输入发不出去。
   - **只有 `schtasks /create … /it /ru qrz` 建的任务会跑在 session 1**；
     用 `Register-ScheduledTask -LogonType Interactive` 建的任务从 session 0
     启动时仍然落在 session 0（本轮实测）。
   - **任务进程还必须切到交互桌面**：它默认在服务窗口站上，
     `SetCursorPos` 直接失败（返回 0）。`SetProcessWindowStation('WinSta0')`
     + `SetThreadDesktop('Default')` 之后光标才动得起来。
     该切换已放进 `lab_driver5`（所有驱动脚本都导入它）。
   - **桌面是与用户共用的**：实机取图时前台是 Chrome（路由器管理页），
     驱动读到的其实是浏览器画面。现在读数前先确认客户端在前台
     （`d.restore_foreground`），必要时把它夺回。
   - 客户端进程在会话重建中存活（23:33 启动）会**卡死输入**：
     `SetCursorPos` 与 `SendInput` 全部无效，键盘也不响应。
     重启客户端后输入立刻恢复 —— 这是本轮最容易误判成"驱动坏了"的现象。

2. **ACT-01 键位与转向速率（实机标定）**
   - **转向速率实测 2.66 rad/s**（四次半秒转向：2.702 / 2.613 / 2.660 / 2.791），
     交接中的 π rad/s 偏大约 18 %，会让每次转向都过冲。
     新常量在 `scripts/client_motion.py`，五个使用点已统一引用。
   - **移动键位非标准**：W 完全不动（位移 0），A/D/S 与方向键才有微小位移。
     交接里"先核对绑定"的提醒是对的。
   - 幽灵不能聊天（服务器答复 "You can't chat when you're dead!"），
     所以它自己发不出任何服务器命令。

4. **REC-01 / NAV-02 幽灵走不出地形（实机确认，未解决）**
   - 尸体在 (0.43715, 0.49199)，幽灵在 (0.4388, 0.4735)，相距 0.0185（约 28 码）。
   - 六种自动脱困全部无效，且每一种都被测量过：
     | 手段 | 结果 |
     | --- | --- |
     | 恢复状态机 240 秒（372 步） | 距离恒为 0.0185 |
     | 新的 `walk_to`（滑行+后退+无进展有界结束）×6 | 每轮 12 步、8 步被挡，`no_progress` |
     | 后退 / 跳跃 / 跳+后退 / 背离尸体 / 背离+跳 / 朝尸体走 | 位移 ≤ 0.00017 |
     | 右键点地（让客户端自己寻路）7 个位置 | 位移 0，客户端也不转向 |
     | 逐键测试 W/A/S/D/方向键 | W=0，D=0.00064，A=0.0002，方向键只转向 |
     | 侧移 A/D 交替 6 次共 18 秒 | 距离 0.01853 → 0.01842 |
   - 探针位置量化步长约 0.0000458，因此上述位移**只有一个到几个量子**：
     角色没有真的移动，只是被挤动。
   - 镜头在岩壁/水面里（整幅画面是墙的纹理），小地图上角色在绿色地面上。
   - **结论：这是服务器侧的"幽灵被地形钉住"，客户端侧无解**。
     交接里"角色卡在地形死角"的说法在现象上成立，但成因比预想更硬。

5. **驱动缺陷（本轮发现并修复）**
   | 缺陷 | 现象 | 修复 |
   | --- | --- | --- |
   | 任务落在 session 0 | 抓屏黑图、输入无效 | 用 `schtasks /it` |
   | 任务在服务窗口站 | `SetCursorPos` 失败 | 导入 `lab_driver5` 时切到交互桌面 |
   | 最小化的客户端被当成占位窗 | 面板读不到 | `is_fullscreen_dummy` 不再把最小化窗口当占位窗 |
   | 前台是别的程序 | 读数是浏览器画面 | 读数前 `restore_foreground` |
   | `find_enter_world` 被动作栏骗过 | 世界画面被当成角色选择 | 搜索范围收窄到动作栏之上；世界判定改用面板能否读出 |
   | 角色列表用硬编码行号 | 选错角色、点空 | 从画面里找名字行与高亮带，自标定 |
   | 转向速率按 π 算 | 每次转向过冲、来回摆 | 实测 2.66 rad/s 统一到 `client_motion` |

## 结论

- 本轮结论只覆盖 3.3.5a (12340) 本机客户端、协议 v14、本机满屏 1920×1080、
  角色 Probehuman（幽灵态）与 2026-11-06 的这一次会话。
- **环境与驱动链路已打通并可重复**：任务进 session 1、切交互桌面、
  前台校验、探针核对、基线读数、输入都实测可用。
- **角色的状态仍然阻塞业务任务**：它是一个走不动的幽灵。
  自动脱困的六种手段都已测量并记录，不能再当作"还没试够方法"。
