# 客户端像素路线：成熟实现与提速建议（2026-11-05）

可查询的问题化整理已收入[客户端知识库](client-kb/README.md)，按现象定位排查顺序与源码；本文保留首次联网研究底稿，后续验证状态在知识条目和独立报告中更新。

## 结论

插件读取状态、色块输出、外部程序读取屏幕并发送键鼠，是已有完整公开项目采用的架构。当前路线有可参考的工程实现，继续推进不必从头探索每一个操作。

本项目效率偏低主要体现在具体实现：战斗逐字输入聊天命令、全屏网格找人、用未知身份的小地图标记充当目的地、缺少地图转换与路线数据、启动/焦点问题反复排查、缺少统一可中断执行器。像素通道本身并不要求这些实现方式。

同时存在关键版本错配：最值得参考的维护分支明确不支持原版3.3.5客户端。因此它能提供架构和模块参照，但不能当作已经适配本机的可运行替代品。3.4.x巫妖王怀旧客户端与3.3.5a原版客户端必须区分。

本次为网上公开资料与源码核查，未安装、构建、部署或运行第三方机器人、代理、客户端；性能与功能声明不作为本机实测。研究不改变现有客户端路线的只读探针约定，也不替代另一窗口正在进行的缺陷修复。

- 固定核对版本：`c5bc4fb614b2054f10b1b377581d39fcb205c2fa`，dev最新提交时间为2026-10-04。
- 固定README：https://github.com/Xian55/WowClassicGrindBot/blob/c5bc4fb614b2054f10b1b377581d39fcb205c2fa/README.md
- 架构文档：https://github.com/Xian55/WowClassicGrindBot/blob/c5bc4fb614b2054f10b1b377581d39fcb205c2fa/docs/architecture.md
- 工程问题文档：https://github.com/Xian55/WowClassicGrindBot/blob/c5bc4fb614b2054f10b1b377581d39fcb205c2fa/docs/technical-challenges.md

实际读取了上述正文、仓库树及若干关键源码。这个项目有DataToColor插件、外部C#读取与决策、键鼠输入、职业配置、商人目标、正常跑尸、路线录制、导航网格与界面诊断，不只是功能名称列表。

与本项目最有用的对应关系：

| 问题 | 公开项目做法/实际源码 | 本项目适用建议 |
| --- | --- | --- |
| 传状态 | Lua色块编码；事件驱动缓存；字段、队列与有效帧标记 | 保留已有实时像素通道；按任务补必要字段与有效性，避免每个场景新写一套观测 |
| 执行动作 | 动作条/按键绑定配置，读取实际绑定；独立施法执行组件 | 战斗优先已验证动作条按键，避免逐字聊天及其焦点/等待开销 |
| 采集 | DXGI桌面采集或WGC指定窗口采集；插件区域单独处理 | 先测固定小区域和稳定窗口几何，再评估DXGI/WGC；不承诺3.3.5 D3D9/虚拟显示/RDP下也能后台采集 |
| 找NPC | 已知NPC位置/功能数据库、导航到附近，再以目标/名字候选/光标类型确认 | 商人先指定名字与短路线，局部识别只做最后确认；不要把全屏盲扫当默认路径 |
| 坐标 | WorldMapArea边界数据将地图坐标转换到世界坐标 | 补地图上下文、版本匹配边界与两轴尺度；缺世界坐标API不等于没有转换方案 |
| 跑图 | 固定路线录制、商人接近短路线；导航网格与路线跟随分工 | 先录一条活人实际走通的短路线，再接通用寻路；路线本身也要核对可逆性 |
| 控制 | GOAP/优先级目标、动作条件及Interrupt看门狗 | 借鉴条件与中断语义；现有Python状态机可继续使用，不要求先改C#或重建GOAP |
| 诊断 | 原始字段、按键绑定、法术书、当前目标/条件、路线和会话统计 | 让一次失败明确落在“数据/条件/动作/后置条件”，减少人工跨工具猜测 |

已核对的关键文件：

- `Core/Goals/AdhocNPCGoal.cs`：从NPC数据库选功能/阵营/位置候选，导航和交互；检查商人/训练窗口，区分窗口已经打开与重复交互关闭的情况。
- `Core/GoalsComponent/CastingHandlerInterruptWatchdog.cs`：独立监视中断条件并取消动作，不把“仍在采样”当成已经能及时中断。
- `Addons/DataToColor/SetupDefaultBindings.lua`：读取动作条/移动/交互等按键并经色块传递；也包含写绑定行为。
- `SharedLib/Data/WorldMapArea.cs`、`WorldMapAreaDB.cs`：有边界转换及XY方向交换。需要匹配地图身份与版本，不直接照抄坐标或混用0–1和0–100。
- `Core/WoWScreen/WowScreenWGC.cs`：使用FrameArrived、TryGetNextFrame与区域复制处理帧；可作为窗口采集的实现参照。
- `Addons/DataToColor/Versions.lua`、`DataToColor_Wrath.toc`：明确有API兼容层，Wrath toc对应30403/30405，而非本机30300。

注意：外部项目的DataToColor包含自动绑定、出售、训练等动作，不符合本仓库“Lua探针只读”的现行约定。可参考观测/地图/配置/调度设计，不能直接部署整套插件后仍宣称只读。GitHub仓库license字段未明确，若后续搬代码须进一步核对具体文件来源与授权；本轮只作架构研究。

## 2. 版本限制是实质问题

README开头明确写：原版Wrath 3.3.5支持不在计划中，机器人依赖该客户端缺失的Interact With Target能力。其导航数据表又列了Wrath3.3.5，这只说明地形年代/导航数据映射，不证明原版客户端整机运行受支持。

issue #704与维护者后续答复是更直接的依据：

- 议题：https://github.com/Xian55/WowClassicGrindBot/issues/704
- 2026-07-26维护者结论：https://github.com/Xian55/WowClassicGrindBot/issues/704#issuecomment-5085807154
- 2026-10-25兼容代理进展：https://github.com/Xian55/WowClassicGrindBot/issues/704#issuecomment-6391478426

议题中有人声称3.3.5可用相近交互，维护者仍明确不支持；故“原版3.3.5缺失该项目依赖能力”是维护者兼容性判断，具体本机按键、CTM、鼠标交互范围仍由A窗口核验。不能从它推出我们现有鼠标交互方案绝对不可行，也不能忽略它继续把项目当作即装即用。

该议题还直接记录法术书、GUID格式、动作条API、地图位置、像素偏移和UI取整问题，和本项目已遇到的失败高度重合。优先读这些已知差异，比逐个临时猜原因更有效。

来源：

- https://github.com/Xian55/HermesProxy/blob/master/wotlk.md
- 本次读取最新release为v4.7.2，发布于2026-11-02：https://github.com/Xian55/HermesProxy/releases/tag/v4.7.2

维护者称现代客户端的交互按键可经代理打开NPC对话；但同时明确尚未把WowClassicGrindBot经该代理端到端跑通。wotlk.md也把兼容性标为experimental，并列出未解决项。因此这是一条有实际兼容工作和测试记录的候选路径，尚不是完整自动化迁移成功证据。

如果希望大量复用维护中的机器人框架，可以安排一次独立兼容性试验，只验证登录/进入同一环境、像素观测、动作条输入与NPC交互四项，然后比较适配成本。需要匹配客户端安装、代理配置及对应API，不应把整个现有环境直接替换成未经验证的新链路。本次仅提出候选，未部署代理或改变连接方式。

3.4.3也不是本项目最初的现代Forever目标；即使该链路可用，也不能据此宣布Forever的Secret Values/Assisted Combat问题解决。

## 5. 对当前工作最实用的调整

1. **保持当前缺陷修复优先**：墓地锚点、严格击杀、失联恢复、连续收尾与整链结果绑定仍需完成；成熟项目不替代我们的验收。
2. **把战斗输入改成已核对的动作条按键**：安全阶段核对技能/等级/资源/键位，运行时外部发键并核事件与效果；聊天保留给必要的诊断或一次性配置。
3. **附近商人以确定数据驱动**：指定真实NPC名字和功能、录一条短路线、靠近后局部确认并开窗。未知NPC发现作为后续独立能力，避免这次交易被通用视觉研究拖住。
4. **地图转换先于扩大小地图探索**：核对地图ID、WorldMapArea等边界和两轴尺度，先验证几个已知点；再接导航网格或已有路径服务。高度、楼层、台阶和路径可逆性须单独验证。
5. **采集做小型独立基准**：在同一安全场景比较当前BitBlt全屏、局部采集和候选WGC/DXGI，记录处理耗时、最大间隔、遮挡/失焦表现。选择以本机数据为准，不先重写整套采集层。
6. **先借鉴模块，再决定是否迁移框架/客户端**：当前Python可以承接同样架构；迁C#、引入完整GOAP、下载全世界导航数据都不是附近商人任务的前置条件。

最小可比较交付是同一场景、同一任务：稳定选目标→动作条施法→明确击杀→拾取→沿已知路到商人→出售指定物品。记录总耗时、人工介入、重试和环境故障，以此判断成熟设计的实际收益。
