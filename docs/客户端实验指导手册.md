# 客户端实验指导手册

本手册是客户端路线（Python 驱动 + Lua 只读探针）的**唯一入口**。
当前流程与历史实测在此集中。历史样本、默认参数和待验证推断不能代替新基线。

> 本手册只描述**客户端路线**。`pure-network/` 是独立工程，不在此范围内。

测试故障先查[客户端问题知识库](client-kb/README.md)，按编号定位排查方法、成熟源码和适用版本；验证完成后按[记录模板](client-kb/07_验证记录与维护.md)补证据。知识库不改变本手册的操作范围。

## 二、环境前提（不满足就会看到"客户端没反应"）

下列条件分别影响启动、采集或输入；不能把任一条件不满足概括成所有输入都失效：

1. **必须运行在用户正在查看的会话里**（控制台会话 / TightVNC）。
   计划任务必须以 `Interactive` 方式、同一用户运行。
   观察者会话里枚举不到游戏窗口，也注入不了输入。
2. **会话不能带 RDP 标记**。3.3.5a 在会话带 RDP 标记时直接拒绝启动：
   `Running World of Warcraft through a Remote Desktop connection is not supported.`
   （`docs/12:60-69`）
   2026-11-02 实测：会话 1 变成 `rdp-tcp#1` 后客户端起不来，弹的就是这句话；
   `tscon 1 /dest:console` 把会话转成控制台会话后客户端正常启动
   （`docs/工作日志_2026-11-01.md:71` 已有同样处置的先例）。
   **起不来时先看这个弹窗，不要去查硬件。**
3. **显示设备**：物理 NVIDIA GTX 1060（无头）+ OrayIddDriver（蒲公英虚拟显示）
   + Virtual Display Driver（支持至 4K@244Hz）。
4. **游戏画面必须可采集**，不能被遮挡或失去渲染。当前驱动默认1920×1080满屏；
   11月1日旧窗口配置曾解码成功，11月3日现行驱动窗口模式仍有缩放/偏移问题。
   两组环境不同，不能推广成任意窗口模式可用。
5. **采集读的是屏幕像素，不是 D3D 表面**，所以读的是虚拟显示驱动复制出来的画面。
6. **输入注入用 `SendInput`**（含 `KEYEVENTF_UNICODE`），在目标会话内运行可被游戏完整接收。
7. **抓屏姿势**：`GetDC(NULL)` + `BitBlt(SRCCOPY|CAPTUREBLT)` + 24 位 BI_RGB。
   `ImageGrab.grab()` 从观察者会话读会拿到**冻结画面**，必须用
   `scripts/client_capture.py` 的 `grab_desktop()`（会话内 BitBlt 屏幕 DC）。
8. **点击坐标是 1920×1080 游戏图坐标，不是屏幕坐标**。窗口不在 (0,0) 且尺寸
   不是 1920×1080 时，直接拿屏幕坐标点会全部点偏
   （2026-11-02 实测：Enter World 按钮真实位置与脚本里的坐标差了 46 像素）。
   用 `scripts/client_geometry.py` 的 `picture_to_screen(hwnd, x, y)` 换算，
   关键按钮（Enter World、Accept）改为**在画面里检测**，不要写死坐标。
9. **驱动任务运行期间不要并发跑别的客户端脚本**。隐藏控制台窗口会把前台
   焦点抢走，游戏就收不到按键，表现为"角色站着不动"。
10. 弹窗、菜单或遮挡期间曾出现遥测冻结/校验失败，具体机制未完全隔离。
    应先识别界面再恢复观测；`client_read_fresh.read_or_dismiss()`用于既定场景，不能在登录画面盲按ESC。

### 客户端现在是满屏 1920×1080

2026-11-02 起驱动默认采用满屏显示；历史实测中仍可被其他窗口遮挡，不以“独占”作为前提。客户端目录 `WTF/Config.wtf` 里
`SET gxWindow "0"`（改之前要**先停客户端**，否则退出时会被写回；
原文件备份为 `Config.wtf.bak-20261102`）。

好处是游戏图与屏幕一一对应，点击坐标不用换算。代价是四个满屏特有的坑：

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 按键全部无效 | 满屏时 `GxWindowClassD3d` 是**离屏 160×28 的占位窗**，PostMessage 进不了游戏 | `lab_driver5.post_key` 改用 `SendInput` |
| `error(1400)` 窗口句柄失效 | 切场景时客户端重建窗口 | `lab_driver5.game_window()` 每次重新取句柄 |
| 几何换算全错 | 占位窗的客户区只有 160×28 | `client_geometry.is_fullscreen()` 特判成恒等映射 |
| 遥测突然解码失败 | 模态窗口把探针冻在半写状态 | `client_read_fresh.read_or_dismiss()` 先关模态 |

另外：旧判据 `ChatFrame1InputFrame:IsShown()` 在 3.3.5a 是**假阳性**
（聊天框关了仍报 true），会让驱动误判"聊天还开着"而反复按 ESC，
把游戏菜单按出来。探针改看 `ChatEdit_GetActiveWindow()`。

### 满屏下最阴的一个坑：客户端被自己的驱动踢退出满屏

`ensure_foreground()` 原来用"窗口矩形在 -32000"判断**最小化**，然后
`ShowWindow(SW_RESTORE)`。而满屏占位窗**恰好也在 -32000**（Windows 还把它
报成 `IsIconic` 为真），于是每次驱动脚本调用 `ensure_foreground` 都会：

1. 把占位窗从 (-32000,-32000,160×28) **恢复成 (0,0,1920×1080)**；
2. 客户端因此**掉出满屏模式**、重建 D3D 设备，**随后自己退出**。

表现就是"客户端莫名其妙每隔几分钟就退一次，而且退出前没有崩溃日志"。
**判断满屏占位窗要靠尺寸**（几百像素宽），不能靠坐标，也不能靠 `IsIconic`。
修法见 `lab_driver5.is_fullscreen_dummy()`。

### 环境侧：Kernel-Power事件与退出原因待核实

2026-11-03 实测：系统日志里反复出现

```
Kernel-Power 566: 系统会话从 61 变为 63 / 从 63 变为 64 / 从 64 变为 66
```

历史记录中这些事件与客户端退出相邻，客户端日志含 `Shutting Down Game Sound`。
事件里的“系统会话”尚未与Windows登录会话ID、进程退出链对照，不能认定每3分钟重建交互会话，
也不能据此认定远程连接抖动或云主机轮换就是根因。该项交B窗口只读核查。

当前用于提高启动与重试能力的措施：
1. **自己重启客户端**（`lab_client_restart.py`）；
2. 启动方式要能**活过启动它的那个任务**——计划任务的作业对象在任务结束时会把
   客户端一起杀掉，所以客户端必须由**另一个常驻的计划任务**启动
   （`lab_client_restart.py` 的 `start_client()`，并带上工作目录，
   否则客户端从 System32 启动会立刻退出）；
3. **能自己重试**：一轮跑不完就重来（`lab_client_standard_run.py`）。

另外 `find_game_window()` 必须**跳过正在销毁的窗口**（客户端切换场景时会有两个
同类的窗口），否则会一直拿到那个已经失效的句柄，报 `no game window`。

### 最阴的一个坑：登录画面上按 ESC 会关掉客户端

2026-11-03 实测（对照实验，一个任务内完成）：
客户端启动 45 秒后**按一次 ESC，6 秒内进程消失**（干净退出，无崩溃日志）。

WoW 3.3.5a 的**登录画面上 ESC = 关闭客户端**。而驱动在登录画面上
**读不到探针面板**（addon 还没加载），于是"读不到就按 ESC 关掉挡住的东西"
这个通用做法会在登录画面上**把客户端杀掉** → 后面全是 `no game window`，
看起来像"客户端起不来"。

修法：`client_read_fresh.read_or_dismiss()` 只在**确认是游戏内菜单**时按 ESC；
在登录画面上只移动鼠标（唤醒客户端），**绝不按 ESC**。
`lab_client_dismiss.py` 里的 ESC 也一并去掉。

### 客户端起不来：先看会话类型（2026-11-04）

现象：客户端**进程能起来，但没有游戏窗口**，桌面上弹出模态框：

```
Running World of Warcraft through a Remote Desktop connection is not supported.
Exiting program.
```

原因：**WoW 3.3.5a 拒绝在 RDP 会话里启动**。今天早些时候能跑，是因为那时交互会话
还是console型的；失败时观测到 `RDP-Tcp#1` 和远程会话标记。RDP启动拒绝有直接弹窗证据，
但其与09:27的Kernel-Power 566之间的因果关系尚待核查。

判定方法（一条命令）：

```python
win32api.GetSystemMetrics(0x1000)   # SM_REMOTESESSION，1 = 远程会话
```

会话清单：`query session`（会话 1 是 `RDP-Tcp#1` 还是 `console`）。

处理：让交互会话回到 console 型——
① 在物理机上退出 RDP 并用 console 登录；或
② `tscon 1 /dest:console`（会话转成本机 console，RDP 画面会掉，之后可重连，
客户端已在运行则不受影响，因为这个检查只在启动时做）。

驱动这边已经能自己读出并关掉这个对话框（`lab_client_restart.py` 的
`client_dialogs()` / `dismiss_dialog()`），但对话框之后客户端已经退出，
所以还是需要会话本身是 console 型。

### 满屏 vs 窗口：驱动为什么用满屏

2026-11-03 实测对比（两个模式都真跑过）：

| | 满屏（`gxWindow "0"`，**默认**） | 窗口（`gxWindow "1"`） |
| --- | --- | --- |
| 探针面板解码 | ✓ 画面就是屏幕，面板位置与布局一致 | ✗ 画面被缩放+偏移到窗口客户区，解码器按 1920×1080 布局找不到面板 |
| 登录 / 角色选择 / Enter World | ✓ 按屏幕坐标点即可 | ✗ 坐标整体错位（实测：账号框点空，停在登录画面） |
| 别的窗口盖住游戏 | 满屏**不是独占的** → 盖住时遥测读不出来 | 客户端可被置前 → 不会被盖住 |
| 客户端失去焦点 | 客户端**把自己的窗口缩成 160×28 的小窗**，画面读不出来 | 窗口不变 |
| 结论 | **驱动默认用满屏**：战斗闭环、危险区整链都在这个模式下跑通 | 需要另外做坐标适配（抓客户端窗口 + 缩放/偏移换算），暂未适配 |

配套要点：

- 驱动任务要用 **pythonw.exe** 跑（不要 `cmd /c python ...`）——
  `cmd` 的控制台窗口会盖在游戏上，桌面抓屏抓到的是那个控制台，遥测就读不出来。
- 客户端**退出时会重写 `Config.wtf`，把 `gxWindow` 那行删掉**，
  所以模式不持久 → `scripts/lab_client_launch.py`（常驻任务 `WowClientRun` 的动作）
  每次启动前都重写一次模式。默认满屏；放 `.cache/desktop-check/windowed.flag`
  则切窗口模式。

### 满屏下的点击安全

满屏客户端画在整个屏幕上，但**它不是独占的**：用户点一下浏览器，浏览器就盖在游戏上，
驱动按屏幕坐标的点击会**落到那个窗口里**（实测点到了用户的 GitHub 页面）。

因此对客户端的点击都走 `lab_driver5.click_client()`：
**先看光标下方那个窗口是不是客户端的**（`WindowFromPoint` + 进程号），
不是就**拒绝点击**。前台窗口是不是客户端**不够**——前台可以是游戏（收键盘），
而可见的画面仍被别的窗口盖着。

同理，**不要去动满屏的绘制面**（`D3DProxyWindow`）：改它的位置/大小/可见性
都会把客户端踢出满屏，客户端随即退出。

### 朝向与地图坐标的实测约定

`scripts/lab_client_heading_calib.py` 与 `scripts/lab_client_walk_calib.py`
标定过方向符号；转向速率是本机实验值，两轴尺度与其他配置需独立核验：

| 项目 | 值 |
| --- | --- |
| 地图 x | 向东为正 |
| 地图 y | 向南为正 |
| 朝向 θ（`GetPlayerFacing()`） | 自北**逆时针**为正 |
| 行走方向符号 | 向量分量符号与 `(-sin θ, -cos θ)` 一致；归一化x/y未证明等尺度 |
| **LEFT 键 / RIGHT 键** | **θ 增大 / θ 减小** |
| 转向速率 | 后续本机标定约π rad/s；早期位移估计约170°/s，不作跨配置常数 |

> 坐标是当前地图上下文的归一化值，不是世界坐标。区域名变化不能证明坐标基准变化；
> Northshire Valley、Elwynn Forest、Goldshire之间的地图层级与转换尚待A/B窗口核验。
> 当前实现尚未支持通用跨区导航或Detour转换，不能从缺少单个API推断技术上做不到。

当前局部控制器使用 `atan2(pos_x - corpse_x, pos_y - corpse_y)` 朝向尸体；两轴物理尺度不同时须加入尺度修正。

> 探针的朝向值编码在 16 位里，**2π 会回绕**。比较角度必须先过 `wrap()`
> 折到 ±π，否则符号会看反（2026-11-02 因此误判过一次转向方向）。

## 五、已验证的踩坑清单

### 输入通道（`docs/客户端输入通道缺陷_2026-11-02.md`）

| 现象 | 真实原因 | 修法 |
| --- | --- | --- |
| 按键完全无反应，角色纹丝不动 | **隐藏的控制台窗口仍是前台窗口**，系统键盘输入进了 cmd 而不是游戏 | `client_chat_guard.ensure_focus()`，**每次**键盘输入前检查 |
| 屏幕上出现 `Say: awwwww` | **聊天输入框吞掉移动键** | `client_chat_guard.ensure_chat_closed()`，用探针 `chat_open` 字段判断后 ESC |
| 遥测突然全部解码失败 | **世界地图遮住了探针面板** | `client_chat_guard.close_world_map()`；小地图点击限制在圆形区域内 |
| 跑任务时角色走着走着停住 | 并发跑的诊断脚本 `hide_consoles()` **抢走了前台焦点** | 驱动任务运行期间不并发跑别的客户端脚本 |
| 客户端起不来，弹窗说 RDP 不支持 | 交互会话挂着 RDP 标记 | `tscon <会话> /dest:console` 转成控制台会话 |
| 点按钮全部点偏 | 坐标是 1920×1080 游戏图坐标，窗口却不在 (0,0) | `client_geometry.picture_to_screen()`，关键按钮改为画面检测 |
| 到尸体了却点不动 Accept | **服务器有复活倒计时**，对话框显示 "N Seconds until resurrection"，按钮是灰的 | 等待式重试（40 × 1.5 s），每轮重新检测红色按钮 |
| 聊天命令没反应，聊天框一直开着 | 满屏时 PostMessage 进不了游戏 | `post_key` 改 `SendInput`；选目标用 TAB 键，别用聊天命令 |

### 战斗与施法（`docs/客户端朝向闭环与恢复演练_2026-11-01.md:105-122`）

| 现象 | 结论 |
| --- | --- |
| 只发 `/target`，怪毫无反应 | **只选中不会拉仇恨**，必须打一发 |
| 射程外开火 | 可能被射程校验拒绝；range错误不是伤害日志中的miss |
| `/face` 命令 | 3.3.5a **没有**这个命令，还额外产生一次 UI 错误 |
| 死亡时 HP 显示 1 或 0 | 两种都出现过，**判死只能看 `dead` 字段** |
| 原地 `S` 后退想脱战 | 已有失败样本；转向前跑在该场景有效，后退速度/障碍/来敌等影响未隔离，不推广为永远无效 |
| 同一名字选出的怪 GUID 每次不同 | 射程属于**当时那个实体**，不能沿用给下一只同名狼 |

### 遥测与协议

- `last_reason` 会被施法事件覆盖成 0 → 协议 v5 起改用独立的 `last_error_reason`
  （只在 UI 错误到达时更新）。
- 原因码5对应 "Target needs to be in front of you."；同一场景也可能先触发range等校验，必须按即时错误区分。
- 3.3.5a缺少当前代码使用的 `UnitDistance`，65535哨兵经编码可变成6552.6等垃圾距离；该字段不用于导航。
- `spell_bits` 只覆盖硬编码候选，ID/名称表有错误且按名字检查不区分同名等级；历史48只证明当时所测位为133/168，不能证明完整法术书。寒冰箭通常有施法时间，不称为瞬发替代方案。
- **探针里凡是像数字的外来值都要 `tonumber` 兜底**。2026-11-02 的大半怪象
  （面板陈旧、AddOns 报错弹窗、UI 有目标而探针看不到、TAB 选不中、
  解码失败）都是 `UnitClassification` 返回**单词** `"normal"` 造成的：
  `math.floor("normal")` 抛错，**一选中目标探针就停止更新**。
  读数对不上时先把客户端的 Lua 错误打开看（`/console scriptErrors 1`）。

## 九、修改约定

- **只读探针**：探针不得调用任何改变游戏状态的接口；
  所有动作走外部输入（键盘、鼠标、聊天指令）。
- **不要重写已有脚本**：先 `grep` 一遍。本项目曾因重复造轮子
  （另写一套复活流程却点错坐标）浪费大量时间。
- **不要凭"看起来没生效"下结论**：判定必须绑定到具体的原因码和证据。
  已发生过两次误判：把「转过去施法还命中」当成转向无效
  （实为射程问题），把「墓地没有释放点」当成死因（实为鬼魂视野渲染）。
- **失败样本原样保留**，不覆盖、不改写 `results/` 里的历史 JSON。
- `.cache/` 与截图是本地证据，不做云备份。
- `pure-network/` 是独立工程，**禁止**修改或加入父仓库。
- **推 GitHub 时某个 IP 不通怎么办**（2026-11-02 实测）：
  `github.com` 解析到的 `20.205.243.166:443` 连不上，
  但 `api.github.com`（20.205.243.168）和 `140.82.112.3` 等都通，
  整体网络没问题（baidu 可达）。换 IP 推送即可：
  ```
  git -c http.sslBackend=schannel -c http.curloptResolve=github.com:443:140.82.112.3 push origin main
  ```
  （`http.sslBackend=schannel` 必须一起带上：系统 gitconfig 里写的是 `openssl`，
  而这个 git 只编译了 schannel，带 `curloptResolve` 时会直接报
  `Unsupported SSL backend 'openssl'`。）
