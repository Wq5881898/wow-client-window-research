# 验证记录：ACT-01 / 游戏内部光标越界 / 2026-11-07

## 范围

本机build12340、协议v14、1920×1080；角色Probehuman，GUID0x8。仅在新解码存活脱战基线后进行UI光标实验。未移动角色、战斗、交易或使用GM命令。

## 直接证据

- 系统光标(960,650)，客户区与窗口均1920×1080、原点(0,0)，但游戏只读API GetCursorPosition返回(8192,-17060.5709)、GetMouseFocus=nil。UI屏幕尺寸1517.0371×853.3334、UIParent有效缩放约0.9。不能直接将游戏坐标与截图像素当同一单位，但该读数明显越界。
- SetCursorPos和WM_MOUSEMOVE没有把游戏内部光标同步到可见区域。
- 大幅负向相对移动后，游戏光标归到(0,767.99998)；正向相对移动可改变内部坐标和悬停对象。说明并非所有鼠标输入均失效。
- 相同输入量的纵向结果存在差异，不能写成通用固定增益或直接代替现有鼠标原语。

## 按钮对照

- `results/client_game_cursor_1794004487804523900.json`：菜单关闭的单次结果，没有保存明确的点击前菜单判据，证明范围有限。
- `results/client_game_cursor_1794004824487305000.json`：明确menu_before_click=true、menu_after_click=true；内部坐标(640,329.14286)，点击未关闭菜单。
- 随后仅补相对纵向1步并点击：`results/client_cursor_final_1794005165343071200.json`记录menu_after=false，截图保留。表明该处按钮能够响应合成鼠标点击，位置同步是关键差异。
- 硬件光标配置读取为gxCursor=1；尝试`/console gxCursor 0`后读数仍为1，不能声称软件光标切换成功。Alt+Enter对照前后窗口几何不变，最终gxWindow仍0，不能声称显示模式实际切换。

只读客户端查询通过外部键盘输入`/run`打印GetCursorPosition/GetMouseFocus/GetScreenWidth/GetScreenHeight/GetCVar，无自动点击、绑定、游戏状态写操作。

## 结论与下一步

已定位到系统光标与游戏内部光标明显不一致，并取得相对移动后按钮可响应的实机样本；尚未建立可靠通用定位器。A1商人交易仍未完成。

下一步只做内部坐标反馈的有界鼠标定位：每步读取真实内部坐标、校验目标控件悬停，再发送按钮按下/释放。不能继续把SetCursorPos成功或系统光标落点当作游戏内命中。优先把这项只读反馈接入现有屏幕探针，避免每一步都慢速聊天查询。协议扩展只服务鼠标闭环，不扩大其他功能。

实验代码在.cache/desktop-check/game_cursor_check.py、cursor_final_step.py，均为本地诊断入口。原始截图保存在同目录，不上传桌面图。失败与复测结果独立保留。
