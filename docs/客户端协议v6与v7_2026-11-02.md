# 协议 v6 与 v7：角色法术与目标分类

> 2026-11-05更正：本文是历史实现记录。下列旧法术表存在ID/名称错误，已在表内标出；当前代码也需A/B窗口核对后修正。位图48仅说明当时所测候选133/168置位，不能推断完整法术书。精英抗性和逐发1点伤害缺逐事件证据；GM命令无效果不能证明无权限；Ghost必须服务端恢复的断言已被后续正常跑尸成功推翻。见[验证分工A5、B2/B3](文档审阅验证任务分工_2026-11-05.md)。

## v6：spell_bits，角色会哪些法术

在 3.3.5a 上探查角色会哪些法术时，只能一个一个试 `/cast <名字>`，
而且失败原因码会把「不会这个法术」和「射程不够」混在一起：
两者都报 reason 1（range）。实测中连火球术都显示成不可用，
因为目标在射程外。

所以协议 v6 新增 `spell_bits` 字段（2 字节，每位一个已知法术）：

| 位 | 法术 ID | 法术 |
| --- | --- | --- |
| 0 | 123 | 旧代码误标Frostbolt；本机名称待核，不按此位证明已学寒冰箭 |
| 1 | 116 | Frostbolt（寒冰箭，通常有施法时间） |
| 2 | 120 | Cone of Cold（冰锥术） |
| 3 | 122 | Frost Nova（冰霜新星） |
| 4 | 133 | Fireball |
| 5 | 168 | Frost Armor |
| 6 | 213 | 旧代码误标Fireball rank 2，本机ID/名称/等级待核 |
| 7 | 212 | 旧代码误标Fireball rank 3，本机ID/名称/等级待核 |

实机读数（`.cache/desktop-check/state-report.json`）：

```json
{"protocol": 6, "spell_bits": 48, "known_spells": [133, 168]}
```

48 = 2^4 + 2^5，即当时火球术与霜甲术候选位为真。不能据错误且不完整的候选表判断全部法术；寒冰箭也不应作为默认瞬发方案。

这一条同时把一个此前的错误结论纠正了：先前认为「寒冰箭不可施放」，
实际是目标在射程外，不是法术缺失。

## v7：target_class，目标是不是精英

在 Elwynn Forest 实机找到的目标全是 **Forest Spider（6 级精英）**：
血条是金色的，名字框也是金色。

对精英打 15 次火球术，每次都"成功"（`cast_succeeded` 递增），
但目标血量始终在 119–120 之间：**一次只掉 1 点**。
原因是精英对低等级法术有抗性，再加上它脱战回血，两次施法之间就补回来了。

所以「目标血量不变」有两种完全不同的原因：

1. 血量**上升** —— 脱战回血；
2. 血量**几乎不动** —— 目标抗性高，打不动。

协议 v7 新增 `target_class` 字段（1 字节），来自 `UnitClassification`：

| 值 | 含义 |
| --- | --- |
| 0 | 无目标 |
| 1 | 普通怪 |
| 2 | 精英 |
| 3 | 稀有精英 |
| 4 | 世界首领 |

解码器同时给出 `target_class_name`。

## 控制器的两条新判定

### 回血检测

`client_combat_controller.py` 在绑定时记录目标血量基线，之后每次观测到
**血量上升**就判定目标脱战回血，把尝试次数预算清零并重新开打，
而不是耗尽预算后失败。

### 抗性检测

新增 `MIN_TARGET_PROGRESS = 5`：如果一次施法之后目标血量下降不到 5 点，
判定目标打不动（`RECOVER / target_resists`），立即放弃而不是继续耗预算。

这个判定只在**实际观察到掉血之后**才做，不会在两帧之间误判：
`cast_health_before` 记录施法前的血量，第一次观测到变化时结算，
之后清空。

## 选目标约束的修正

血量上限从 45 放宽到 130：

- 45 太严，普通 6 级怪有约 120 血，根本找不到目标；
- 真正的约束不是血量，而是**目标类型**（精英打不动）和**是否逃跑**。

`lab_client_combat_loop.py` 与 `lab_client_hunt.py` 现在都拒绝
`target_class > 1` 的目标。

## 仍未验证

- 没有找到普通怪完成一次完整击杀。本轮所有可见的敌对目标都是精英。
- 精英怪的正确打法（拉开距离、连续施法、等它脱战再打）没有验证。
- `spell_bits` 只覆盖 8 个已知法术。角色若学会别的法术，探针不会报告。
- 血量上限 130 是按 6 级普通怪的经验取的，没有针对更高等级标定。

## 附带的发现：这个账号没有游戏主权限

`scripts/lab_client_teleport.py` 依次尝试了

```
.gm on
.tele GM01 42 62
.tele Northshire Valley 42 62
.tele GM01 42.5 62.5
```

当时未观察到预期效果，位置没变（0.5019455252918288, 0.4877546349279011）。`.gm on`本来不以位移为后置条件，所试`.tele`语法与realm权限尚未核对。

由上述现象不能确定GM01权限。早期数据库记录与当前状态须由B窗口只读核实；不再把命令没效果当成无权限证明。

这也让 Probehuman 无法复活这件事有了一个更准确的解释。
角色选择界面把它标成 `Level 1 Mage (Ghost)`，说明**服务端存的就是一个鬼魂状态**。
野外死亡后客户端会给出 "Resurrect now?" 的免费复活，
但**服务端不会主动把一个已经被存成 Ghost 的角色救回来**——
野外免费复活是死亡瞬间由客户端发起的，请求会被拒绝，因为角色已经不在「刚死亡」的状态里。

之前把这件事归因为「该墓地区域没有释放点蜡烛」是**不准确的**：
整个墓地呈幽灵着色、没有暖色光源，只是鬼魂视野的渲染效果，
不能证明那里没有释放点。
