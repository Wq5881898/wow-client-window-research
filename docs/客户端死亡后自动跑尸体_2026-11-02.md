## 一、任务定义

角色死亡后成为幽灵，需要走到自己的尸体上，客户端才会弹出回收对话框；
确认对话框后角色复活并脱战。任务由三部分组成：

| 部分 | 文件 | 职责 |
| --- | --- | --- |
| 观测 | `probes/WowProbeWotLK/WowProbeLive.lua`（协议 v8） | 报告角色朝向与尸体位置 |
| 决策 | `scripts/client_corpse_runner.py` | 纯函数状态机，只决定下一步动作 |
| 执行 | `scripts/lab_client_corpse_run.py` | 把决策翻译成键盘/鼠标输入并验收 |

决策层不碰任何 Windows 接口，因此每一条分支都能离线测试
（`scripts/test_client_corpse_runner.py`，17 条用例）。

状态机阶段：

| 阶段 | 触发条件 | 动作 |
| --- | --- | --- |
| `SEEK_CORPSE` | 距离尸体 > `CORPSE_RANGE`(0.004) | 转向对准尸体，或前走 |
| `AT_CORPSE` | 距离 ≤ 0.004 | `ACCEPT`（点对话框按钮） |
| `DONE` | `dead` 字段变 false | 结束，验收存活/脱战 |
| `FAILED` | 时间预算耗尽 / 没有尸体 / 对话框点不动 | 记录原因后退出 |

## 二、协议 v8

| 版本 | 字节 | 新增字段 |
| --- | --- | --- |
| v8 | **115** | `facing` 改为真实朝向、`corpse_x`、`corpse_y`、`corpse_exists` |

- 3.3.5a **没有** `GetUnitFacing`，但**有** `GetPlayerFacing()`。
  v3–v7 的 `facing` 字段虽然一直在传输，值却恒为 0；v8 起它才真正有意义。
- 尸体位置来自 `GetCorpseMapPosition()`，越界/不存在时返回 `(0,0)`，
  因此 `corpse_exists` 用 `cx ~= 0 or cy ~= 0` 判定。
- v3–v8 各有独立布局表，**历史截图仍可解码**；
  `scripts/client_live_layout.py` 是布局唯一真相源。

## 三、实机标定出来的约定（本任务的核心）

这些约定全部是**测出来的**，不是假设的。标定脚本：
`scripts/lab_client_heading_calib.py`（转向）与
`scripts/lab_client_walk_calib.py`（行走）。

| 项目 | 实测值 | 备注 |
| --- | --- | --- |
| 地图 x | 向**东**为正 | |
| 地图 y | 向**南**为正 | 与"地图图片左上角为原点"一致 |
| 朝向 θ | 自北**逆时针**为正 | `GetPlayerFacing()` |
| 行走位移 | `u(θ) = (-sin θ, -cos θ)` | 归一化地图单位 |
| **LEFT 键** | **θ 增大** | |
| **RIGHT 键** | **θ 减小** | |
| 转向速率 | **π rad/s**（正好半转/秒） | 1.0 秒按键 = 180° |

由此推出朝向尸体的目标角：

```
θ_target = atan2(pos_x - corpse_x, pos_y - corpse_y)
```

因为 `-sin θ ∝ corpse_x - pos_x`、`-cos θ ∝ corpse_y - pos_y`。
检验：尸体在正东 → θ = -π/2（北的顺时针 90°）✓；正南 → θ = π ✓。

### 一个把人带偏的假象

探针的朝向值是 `floor(facing * 10430)`，编码在 16 位里，
**2π 会回绕**。第一次标定时"按 RIGHT 朝向反而增大"的结论，
其实是 `0.5434 - π = -2.598` 回绕成 `+3.685`。所有角度比较
必须先过 `wrap()`（折到 ±π），否则符号会看反。

## 四、踩过的坑

| 现象 | 真实原因 | 修法 |
| --- | --- | --- |
| 客户端根本起不来，弹窗 `Running World of Warcraft through a Remote Desktop connection is not supported.` | 交互会话挂着 RDP 标记 | `tscon 1 /dest:console` 把会话转成控制台会话，再重启客户端（`docs/工作日志_2026-11-01.md:71` 已有先例） |
| 点了 Enter World 没有任何反应 | 客户端窗口不再是 (0,0) 1920×1080，**所有点击坐标都是 1920×1080 游戏图坐标**，直接当成屏幕坐标就点偏了 | 新增 `scripts/client_geometry.py`：`picture_to_screen()` 按窗口客户区做换算；Enter World 按钮改为**在画面里检测**（`find_enter_world()`） |
| 走路按键时灵时不灵 | 另一个脚本调用 `hide_consoles()` 隐藏控制台窗口，**抢走了前台焦点**，游戏收不到按键 | 驱动任务运行期间不得并发跑任何会隐藏窗口的诊断脚本；每次输入前 `ensure_focus()` |
| 按钮检测点到聊天框的金色像素 | 检测条件太松 | Accept 按钮是**纯红** `(112,1,0)`，在画面上半部中间搜 `r>90 且 r>2.2g 且 r>2.2b` 的连续块 |
| 转向方向与预期相反 | 见上面的 2π 回绕 | 统一用 `wrap()` 比较角度 |

### 关于"走不动"

墓地被石栏围住，直线走向尸体可能被挡。状态机带绕行逻辑：
**一次前走没有让距离变近**，就沿反方向偏一个角度再试，
偏角逐次加大（0.45 + 0.3n rad，上限 1.6 rad），一旦走通就回到直线。

## 六、怎么再跑一次

```
scripts/lab_client_enter_character.py --character Probehuman   # 先进世界
scripts/lab_client_corpse_run.py                              # 跑尸体任务
```

前置条件：角色处于 Ghost 状态且客户端报告 `corpse_exists=1`。
没有尸体时脚本以 `status: NO_CORPSE` 退出，不会乱走。

**运行期间不要并发跑别的客户端脚本**（会抢焦点）。
