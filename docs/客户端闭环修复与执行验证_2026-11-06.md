## 逐条实际结果

1. **CTL-01 动作取消与异常出口（离线通过）**
   - 新增 `scripts/client_action_guard.py`：`ActionGuard` 把"必须停手"的原因
     **锁存**，第一个原因被保留；`ActionCancelled` 把原因带给调用方。
   - `cast()` 现在**使用**检查的返回值：检查给出原因时，输入线程停止打字
     （`threading.Event`），异常被抛出而不是被吞掉；读数失败（初始读与过程中读）
     转为 `reading_failed` 并停止动作。
   - `move_while_watching()` 同样返回原因；`hold()` 接受停止事件，被取消时**立即释放按键**。
   - TURN 扫描的施法改为与普通施法共用同一套检查（此前只刷心跳）。
   - 接近阶段（进入射程前）也接入守卫。
   - 恢复触发后守卫被锁存，重绑目标不能清除已触发的恢复决定。
   - 反例：`scripts/test_client_combat_cancel.py` 6 项（被取消的施法抛异常、
     不打完整个命令、正常施法照常打出命令、读数失败停止施法、
     被取消的移动释放按键、正常移动保持按键）。

2. **ACC-03 连续安静验收（离线通过）**
   - 新增 `scripts/client_survival_watch.py`：`SurvivalWatch` 按**相邻两次观测的时间差**
     累计安静时长；任何一次破坏条件的观测把时长**清零**。
   - 条件：存活、脱战、静止（speed=0）、玩家 GUID 不变、**面板序号必须前进**
     （重复画面不算观测）。
   - 威胁：把**有效值**与**未知值（255）**分开统计；未知值不再掩盖其他有效读数；
     有未知样本时 `threat_available=False` 并写明"清仇恨不可证"。
   - 原实现只累计观测总时长，且"安静"只是没有被使用的样本计数。
   - 反例：`scripts/test_client_survival_watch.py` 8 项（最后时刻才脱战不算通过、
     移动打断、死亡打断、换角色打断、重复画面不算观测、摘要列出打断原因、
     时间按间隔增长、完整安静区间通过）。

3. **ACC-02 父子任务与结果绑定（离线通过）**
   - 父任务给每个步骤 `--parent-run <run>` 与 `--attempt <n>`；
     子任务用 `client_parent_run.stamp()` 把这两个标识写进自己的结果。
   - `problems_of()` 现在**拒绝缺结果文件的步骤**（此前直接跳过）；
     并检查：结果属于本次 run、文件名与结果内的 `run` 一致、
     后置条件成立、恢复步骤必须有**第二次死亡**（`second_death == 'happened'`）。
   - 新增 `enter` 步骤的后置条件（`IN_WORLD`）。
   - 汇总不再用 `latest()` 引入别的轮次的结果；固定入口
     `results/client_full_acceptance.json` 改为**只作索引**，指向本次不可变报告
     `results/client_full_acceptance_<run>.json`，并列出历史报告路径。
   - 报告增加逐次尝试的耗时、总耗时与问题清单。
   - 反例：`scripts/test_client_full_acceptance.py` 16 项（含缺结果被拒、
     错父 run 被拒、文件名与内容不符被拒、缺第二次死亡被拒、
     只有撤退成功被拒、结果不可读被拒）。

4. **NAV-02 绕障与走路（离线通过，实机仍待验证）**
   - **转向不再算撞墙**：只有"本该前进却没动"的步才计入被挡。
   - **绕障状态单一归属**：`Obstacle` 独占被挡计数与绕行侧；
     `walk_to()` 不再自己加计数（此前两处各加一次，同一步被数两遍）。
   - `walk_to()` 现在返回结构化结果：是否到达、距离、被挡次数、步数、
     走过的距离、**结束原因**（`no_progress` / `no_focus` / 到达）。
   - **无进展有界结束**：连续 12 步没有更近就带原因结束，不再"看起来还在路上"。
   - **焦点失败可观测**：客户端窗口无法置前时抛出 `FocusLost`，
     走路以 `no_focus` 结束；此前异常被吞掉，照样发按键。
   - 终点判定：**转向不算碰撞**、**计数不重复**两条都有离线反例
     （`scripts/test_client_walk_obstacle.py` 6 项）。

5. **NAV-01 回出生点的地图上下文（离线修复，实机仍待验证）**
   - 旧脚本用 `zone_hash == name_hash('Northshire Valley')` 判定"已进北郡"，
     但实机读到的 `zone_hash=48885`（Elwynn Forest），Northshire Valley 出现在
     **subzone**。判定因此永不成立 —— 这是代码错误，不能只归因于角色卡在地形里。
   - 改为 zone 与 subzone 都检查；**并且**在谷外不再盲用出生点坐标
     （该坐标属于北郡基准），只用小地图任务标记给方向。

6. **REC-01 恢复状态机（离线通过，实机仍待验证）**
   - **任务级终点**：`_start_death()` 不再清空 `graveyard`；
     终点是任务的属性，第二死亡与第一次有同一个终点。
     每次幽灵出现的地点另存 `releases`（含 `is_the_end` 标记）。
   - **一次死亡一具尸体**：复活对话框可能被点多次，
     现在按死亡编号去重，不再把重复点击记成多具尸体。
   - **威胁未知不再空等**：威胁期限只设定一次（此前每轮 DONE 分支重设，
     导致未知威胁下一直等到总预算耗尽）；255 单独记为"读不到"。
   - 走直线去终点的兜底被标记为 `route_was_direct`，
     不再当作"已走通幽灵路径"的证据。
   - 缺第二次死亡时结果记 `second_death='not happened'`，由父任务判为未完成。
