# 客户端朝向闭环与恢复演练

## 背景

上一轮的战斗闭环验收只覆盖了"打赢了"这一条路径。剩余缺口是：
玩家受伤后能否自行脱战、施法时朝向不对能否自动修正。

## 一、受伤恢复演练（已通过）

`results/client_recovery_1793522398295220600.json`：`RECOVERY_DRILL_PASSED`。

演练步骤全部由脚本驱动：先上霜甲术减伤，走到火球术射程内，打一发拉仇恨，
然后**停手挨打**，直到血量跌破阈值。状态机必须自行判定 `RECOVER / low_health`，
随后自动脱战。

| 项目 | 值 |
| --- | --- |
| 起始血量 | 52/52 |
| 触发时血量 | 36/52（比值 0.692，阈值 0.70） |
| 受伤次数 | 15 次 |
| 撤退途中最低血量 | 32/52 |
| 最终状态 | 52/52，脱战，静止 |

血量时间线：52→51→50→49→48→47→46→45→44→43→42→41→39→38→37→36。

### 撤退必须转向，不能原地后退

第一次尝试只用 `S` 键后退，**失败**：
`results/client_recovery_1793520565646955000.json` 记录了 16 次受伤、
阈值正确触发，但 6 次后退后位置几乎不变（`pos_x` 恒为 0.4908），
`combat` 始终为 `True`，最终 `retreat did not clear combat`。

原因是 `S` 只沿当前朝向后移，而狼就贴在正前方追击
（截图 `client_recovery_1793520565646955000_06-recovery-trigger.png`：
狼名牌就在角色头顶）。沿着追击方向后移等于沿着狼的路线走。

改成**先左转再前跑**后成功，4 步内脱战，每步位置都变化：

| 步骤 | 血量 | combat | 位置 |
| --- | --- | --- | --- |
| 0 | 35 | True | 0.5005, 0.4384 |
| 1 | 34 | True | 0.5005, 0.4323 |
| 2 | 33 | True | 0.4965, 0.4326 |
| 3 | 32 | **False** | 0.4968, 0.4365 |

该原语已抽到 `scripts/client_retreat.py` 的 `break_engagement()`，
战斗闭环的恢复分支也改用它。

### 顺带修掉的一个隐患

`lab_client_combat_loop.py` 原来在血量低于 70% 时直接抛异常中止，
这会把角色留在战斗里——正是 2026-10-29 死亡事故的同一类错误。
现在改为进入恢复分支。

## 二、协议 v5：修复原因码被覆盖

### 发现的真实错误

截图 `client_loop_recover_1793524106991149400_06-end.png` 上有客户端自己的
红字 **"Target needs to be in front of you."**。但探针报告的是 `reason=0`
（未知）。

两个原因：

1. **文本匹配漏了这条**。探针只匹配 "facing"，而实际文本是 "in front of you"。
2. **`last_reason` 会被覆盖**。`last_reason` 记录的是"最后一个事件"的原因，
   而施法失败事件（kind=3）总是推 reason=0，会把先前的 UI 错误原因冲掉。

### 改动

- `reason_code()` 增加 "in front of you" 匹配，并把更具体的判断提到前面
  （原来的 "dead" 检查会先吃掉很多文本）。
- 协议升到 **v5**，107 字节，新增 `last_error_reason` 字段：
  **只在 UI 错误到达时更新**，不会被施法事件覆盖。
- v5 在 `last_reason` 之后插入新字段，v3/v4 的所有历史截图仍可解码。
  布局测试强制 Lua 编码顺序与 Python 解码偏移一致。

面板显示 `LIVE v5 ... reason=0 er=0`，新字段已上线。

### v4 布局不变

`last_reason` 之后的字段在 v5 里整体后移 1 字节，但 v3/v4 各自独立布局表，
历史截图不受影响。`test_v5_only_inserts_after_the_v4_fields` 固化了这一点。

## 三、朝向闭环

3.3.5a 没有 `GetUnitFacing`，朝向字段恒为 0，驱动侧无法询问角色朝向。

但客户端自己会回答这个问题：目标不在正前方时，施法失败并提示
"Target needs to be in front of you."。探针把这个提示翻译成原因码 5，
于是**客户端的错误码就是转向的反馈信号**。

`scripts/client_facing.py`：

- `turn_step(direction)`：按一次转向键。
- `sweep_toward(cast)`：反复施法，每次检查 `last_error_reason`，
  仍是 5 就转一小步再试，直到原因消失。

`client_combat_controller.py` 新增 `TURN` 决策分支：
原因码 5 不再走 `CLOSE_DISTANCE`（走近并不能让目标转到正前方），
而是走 `TURN`。战斗闭环已接入该分支。

离线测试 71 项全部通过。

## 四、期间踩到的坑

1. **只选中不会拉仇恨**。只发 `/target`，狼毫无反应，脚本空转 90 秒超时。
   必须打一发才会进战。
2. **射程外开火会 miss**。有一轮火球术 `succeeded` 但目标血量不变、
   `combat=False`，因为角色背对目标。
3. **`/face` 无效**。3.3.5a 没有这个命令，客户端回 "Type '/help' for a listing
   of few commands."，还额外产生一次 UI 错误。
4. **死亡时血量显示 1 而非 0**。角色死亡后探针报告 `HP 1/52`，
   但 `dead=1`。用 `health <= 0` 判死会漏判，必须看 `dead` 字段。
   另一轮死亡报告的是 `HP 0/52`——两种都出现过，判死只能用 `dead`。
5. **探针面板挡住复活 NPC 菜单**。面板原本固定在左上角，正好盖住
   目标框、名牌和复活 NPC 的右键菜单，导致 "Accept Resurrect" 那一行
   被面板文字覆盖、无法点击。已把面板移到左下角，解码器搜索范围相应
   改为全屏高度。
6. **证据截图标签重复会互相覆盖**。`Evidence.capture` 用固定标签生成文件名，
   同一标签重复使用时后者覆盖前者，而 frames 列表里却留下多条同名条目。
   现在重复标签自动加序号。

## 五、仍未验证

- **转向闭环的实机验证没有完成**。代码、协议字段和决策分支都已就位，
  但反复的实机尝试都被"角色死亡后的复活流程"卡住：墓地状态下客户端
  弹出的是 NPC 交互菜单（Spirit Healer / Set Focus / Reset all instances 等），
  而野外死亡时才有 "Resurrect now?" 对话框（Accept 在 960, 252）。
  `lab_client_safe.py` 已能处理野外对话框，墓地分支仍未打通。
- 撤退依赖"转向 + 前跑"这一组盲按键，因为 3.3.5a 没有朝向读数。
  多狼追击、绕障场景下的脱战成功率未测。
- 低血阈值 70% 有了实测依据（触发于 0.692），但只在 1 级狼约 2.5 秒的
  攻击节奏下验证过；面对更快或会远程攻击的敌人需要重新标定。
- 目标距离字段实测恒为 0（`UnitDistance` 在该服务端返回 0），
  仍不能用于导航。
- 中文界面的错误文本仍只匹配英文关键字。
