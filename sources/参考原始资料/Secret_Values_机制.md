### Secret values

*   Combat API functions may now return secret values when called, for example [UnitHealth](https://warcraft.wiki.gg/wiki/API:UnitHealth "API:UnitHealth")(unit).
*   Tainted code generally cannot perform operations on these secret values except for storing them in variables or table fields, or passing them to other functions.
*   A limited set of native APIs will accept secret values from tainted code, for example [StatusBar:SetValue](https://warcraft.wiki.gg/wiki/API:StatusBar_SetValue "API:StatusBar SetValue")(value). 
    *   For widget API methods, this ties into the Secret Aspects system discussed later.

*   When execution is not tainted secret values are effectively equivalent to regular values, and no operations on them are blocked.

AddOns can test secrets via the following functions.

*   [issecretvalue](https://warcraft.wiki.gg/wiki/API:issecretvalue "API:issecretvalue")(value) returns true if the supplied value is secret.
*   [canaccessvalue](https://warcraft.wiki.gg/wiki/API:canaccessvalue "API:canaccessvalue")(value) returns true if the calling function has permission to perform operations on secret values.

#### Restrictions

The full list of technical restrictions for tainted code is as follows.

*   When an operation that is not allowed is performed, the result will be an **immediate** Lua error.
*   Tainted code is allowed to store secret values in variables, upvalues, or as values in tables.
*   Tainted code is allowed to pass secret values to Lua functions. 
    *   For C functions, an API must be explicitly marked up as accepting secrets from tainted callers.

*   Tainted code is allowed to concatenate secret values that are strings or numbers. 
    *   Tainted code is additionally allowed to call APIs such as [string.concat](https://warcraft.wiki.gg/wiki/API:string.concat "API:string.concat"), [string.format](https://warcraft.wiki.gg/wiki/API:string.format "API:string.format"), and [string.join](https://warcraft.wiki.gg/wiki/API:string.join "API:string.join") with secret values.

*   Tainted code is not allowed to perform arithmetic on secret values.
*   Tainted code is not allowed to compare or perform boolean tests on secret values. 
    *   As an exception, tainted code _is_ allowed to perform boolean tests on non-boolean type secrets. Since the type isn't secret; nil always evaluates as false, and all other types besides boolean always evaluates as true.

*   Tainted code is not allowed to use the length operator (`#`) on secret values.
*   Tainted code is not allowed to store secret values as keys in tables.
*   Tainted code is not allowed to perform indexed access or assignment (`secret["foo"] = 1`) on secret values.
*   Tainted code is not allowed to call secret values as-if they were functions.
*   Querying the type of a secret value `type(secret)` returns its real type (ie. "string", "number", etc.).

#### Secret tables

For Lua tables, a few additional restrictions apply.

*   A table can be flagged such that indexed access of it will always yield a secret value.
*   A table can be flagged as inaccessible to tainted code; any attempt to index, assign, measure, or iterate over such a table will trigger an **immediate** Lua error ("attempted to index a forbidden table").
*   When untainted code stores a secret value as a table **key**, the table itself is irrevocably marked with both of the aforementioned flags.

A few additional APIs exist to handle table secrecy.

*   [issecrettable](https://warcraft.wiki.gg/wiki/API:issecrettable "API:issecrettable")(value) returns true if the supplied table is secret.
*   [canaccesstable](https://warcraft.wiki.gg/wiki/API:canaccesstable "API:canaccesstable")(table) returns true if the calling function would not error if attempting to access the table.

### API documentation changes

The autogenerated API documentation has been expanded to detail how APIs work with secrets.

*   [![Image 4: Townlong-Yak BAD.png](https://warcraft.wiki.gg/images/thumb/Townlong-Yak_BAD.png/16px-Townlong-Yak_BAD.png?ca02cf)](https://www.townlong-yak.com/framexml/latest/Blizzard_APIDocumentation#s:SecretReturns) Functions that unconditionally return secret values are marked as `SecretReturns = true`.
*   Functions that conditionally return secret values also exist. 

#### Secret arguments

*   Whether a function accepts secret values as arguments is documented via the `SecretArguments` field. 

#### Secret predicates

Many C API functions return secrets conditionally through a system of secret predicates that are only active when certain addon restrictions are enabled.[[1]](https://warcraft.wiki.gg/wiki/Secret_Values#cite_note-1)

*   A new [C_RestrictedActions](https://warcraft.wiki.gg/wiki/Category:API_systems/RestrictedActions "Category:API systems/RestrictedActions") namespace has been added with APIs to test current addon restriction states.
*   A new [C_Secrets](https://warcraft.wiki.gg/wiki/Category:API_systems/SecretUtil "Category:API systems/SecretUtil") namespace has been added with APIs that allow direct evaluation of secret predicates.

### Forbidden aspects

> Forbidden Aspects are another new construct that works alongside Private Script Objects. Forbidden Aspects are similar in concept to the Secret Aspects we introduced in Midnight, but instead of causing certain object APIs to return secrets, they prevent addons from using certain functionality entirely. Where Secret Aspects obfuscate data, Forbidden Aspects restrict what addons are allowed to do with an object.
> 
> 
> There are several Forbidden Aspects being added (details are in the docs), but let’s use the UntrustedScriptExecution Forbidden Aspect as an example. When a frame has the UntrustedScriptExecution Forbidden Aspect applied to it, any script binding handlers set on it (e.g. OnShow, OnLoad, OnSizeChanged) will not be run unless that handler lives in the object’s Forbidden Partition and execution is untainted. In other words, addons cannot install their own script bindings on the object, but our code can.

### Secret anchors

An API that accepts secret values but has no connected aspect will instead mark the entire object as having secret values.

*   As an example, calling [StatusBar:SetValue](https://warcraft.wiki.gg/wiki/API:StatusBar_SetValue "API:StatusBar SetValue")(value) with a secret numeric value does not apply an explicit aspect. Instead, the object itself is marked as having secret values.
*   Objects marked as having secrets will cause all APIs to return secret values unless those APIs derive secrecy from secet aspects.
*   The application of this state can be tested via [FrameScriptObject:HasSecretValues](https://warcraft.wiki.gg/wiki/API:FrameScriptObject_HasSecretValues "API:FrameScriptObject HasSecretValues")().

An object that is marked as having secret values (rather than aspects) has implications on anchoring and position APIs.

*   Objects marked as having secret values also mark all anchoring and positioning data on the frame as being secret.
*   The secrecy of anchoring and position data propagates downwards to dependent anchored regions. 
    *   If child frame B is anchored to parent frame A, and A has secret anchoring data, B implicitly has secret anchors too.

*   Calling position or measurement APIs on a region with these secrets will return secret values.
*   The [ScriptRegion:IsAnchoringSecret](https://warcraft.wiki.gg/wiki/API:ScriptRegion_IsAnchoringSecret "API:ScriptRegion IsAnchoringSecret")() API can be used to test this state.
*   Clearing anchor points can reset this state.

### Constant accessors

Some APIs are marked as constant secret accessors. Calling these functions with secret values does not apply any aspects nor does it mark the object as having secret values, however the return values of the function will be implicitly secret.

*   [![Image 129: Townlong-Yak BAD.png](https://warcraft.wiki.gg/images/thumb/Townlong-Yak_BAD.png/16px-Townlong-Yak_BAD.png?ca02cf)](https://www.townlong-yak.com/framexml/latest/Blizzard_APIDocumentation#s:ConstSecretAccessor) An example of one such function is [ScriptRegion:GetHeight](https://warcraft.wiki.gg/wiki/API:ScriptRegion_GetHeight "API:ScriptRegion GetHeight")(ignoreRect). 
    *   This function assigns nothing to the frame, so if it were called with a secret boolean value it shouldn't apply any aspects or mark the object as having secret values.
    *   The returns of this function however would be secret if any of its parameter were itself secret.

### Curves and ColorCurves

[Curve](https://warcraft.wiki.gg/wiki/ScriptObject_CurveObject "ScriptObject CurveObject") and [ColorCurve](https://warcraft.wiki.gg/wiki/ScriptObject_ColorCurveObject "ScriptObject ColorCurveObject") objects have been added to give addons a way to programmatically display secret values without being to inspect or otherwise operate on those values. Color curves can do standard operations like health bar coloring (for example, from green → red for 100% → 0% health). Create one with [C_CurveUtil.CreateCurve](https://warcraft.wiki.gg/wiki/API:C_CurveUtil.CreateCurve "API:C CurveUtil.CreateCurve")() and [C_CurveUtil.CreateColorCurve](https://warcraft.wiki.gg/wiki/API:C_CurveUtil.CreateColorCurve "API:C CurveUtil.CreateColorCurve")().

### Durations

[Duration](https://warcraft.wiki.gg/wiki/ScriptObject_DurationObject "ScriptObject DurationObject") objects are returned instead of numbers and allow addons to perform calculations natively on potentially secret data and return secrets back to Lua. Create one with [C_DurationUtil.CreateDuration](https://warcraft.wiki.gg/wiki/API:C_DurationUtil.CreateDuration "API:C DurationUtil.CreateDuration")(). These can be passed to [StatusBar:SetTimerDuration](https://warcraft.wiki.gg/wiki/API:StatusBar_SetTimerDuration "API:StatusBar SetTimerDuration")().

## Console variables

A handful of console variables are available to simulate secrecy. They will not be saved across game restarts.

| Console Variable | Description |
| --- | --- |
| addonMapRestrictionsForced | If set, APIs guarded by current map type will be restricted, or may return secrets. |
| addonChatRestrictionsForced | If set, APIs guarded by in lockdown will be restricted, or may return secrets. |
| addonCombatRestrictionsForced | If set, APIs guarded in combat will be restricted, or may return secrets. |
| addonPvPMatchRestrictionsForced | If set, APIs guarded by PvP match state will be restricted, or may return secrets. |
| addonEncounterRestrictionsForced | If set, APIs guarded in active encounters will be restricted, or may return secrets. |
| addonChallengeModeRestrictionsForced | If set, APIs guarded by challenge mode and mythic plus status will be restricted, or may return secrets. |
